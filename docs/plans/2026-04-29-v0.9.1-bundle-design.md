## Per-story design

### US-001 — Real-LLM dogfood through `--coordinator`

**Approach:** Use a worktree (existing `.ql-wt/` pattern) to isolate the dogfood. Worktree gives a full repo tree (so `agents/coordinator.md`, `lib/spawn.sh`, `CLAUDE.md`, etc. are all visible) plus a throwaway branch (so coordinator/implementer commits don't pollute master).

**Worktree path:** `.ql-wt/dogfood-v091/` on throwaway branch `dogfood-v091-runtime` from master HEAD.

**Synthetic plan (`tasks/prd-dogfood-v091.md` + worktree-local `quantum.json`):**

Two trivial stories on disjoint files (so they go in the same wave — no fileConflicts split):

- **US-A:** Append a 1-line shell-comment to `dogfood/target-A.sh` (file pre-created with a placeholder line).
- **US-B:** Append a 1-line shell-comment to `dogfood/target-B.sh` (file pre-created with a placeholder line).

Each task: `testFirst=false`, single command (e.g., `grep -q "## v0.9.1 dogfood mark A" dogfood/target-A.sh`), trivial AC.

**Fire command:**

```bash
cd "$REPO_ROOT/.ql-wt/dogfood-v091"
QL_AUTONOMOUS=1 bash quantum-loop.sh --coordinator --max-iterations 5 2>&1 | tee dogfood-stdout.log
```

**Capture (saved alongside the worktree):**
- `dogfood-stdout.log` — full stdout from the parent shell
- `quantum.json` post-run state — committed by the parent
- `git log --oneline` — implementer commits

**Acceptance Criteria:**
- [ ] `.ql-wt/dogfood-v091/` worktree exists with full synthetic plan + 2 target files.
- [ ] `bash quantum-loop.sh --coordinator` invoked end-to-end against the worktree's `quantum.json` with `RUNNER_NAME=claude`.
- [ ] `dogfood-stdout.log` captured; non-empty; contains either a `<quantum>WAVE_*` signal or an explicit failure.
- [ ] Post-run `quantum.json` snapshot saved; `stories[].status` and `stories[].review.*` fields readable for US-002 to analyze.
- [ ] Wallclock + token-count rough estimate logged in the findings doc.

**Honest failure-modes acknowledged:**
- Real coordinator subagent drifts mid-wave → same N33-class drift; would mean architectural fix is bigger.
- `spawn_coordinator` command-string construction has a bug not caught by stubs.
- `review.*` field writes don't actually populate per the contract.
- Wave-eligibility logic edge case under realistic complexity.

If any surface, we ship the diagnostic finding (US-002) + the inline fix (US-003).

### US-002 — Capture findings

**Approach:** Read `dogfood-stdout.log` + post-run `quantum.json` + `git log` from the worktree. Write `idea-stage/dogfood-v0.9.1-findings.md` with sections for each architectural question:

1. Did `next_wave` fire correctly? (Look for "wave-1" mention, story-id list)
2. Did `spawn_coordinator` produce reachable output? (Was `eval "$COORD_CMD"` non-empty?)
3. Did per-story aggregation route WAVE_PASSED/WAVE_FAILED correctly? (Compare expected vs actual `stories[].status`)
4. Did coordinator stay bounded per wave? (Was the coordinator subagent's transcript scoped to ONE wave or did it drift?)
5. What unexpected behaviors surfaced?
6. Streak status: did v0.9.1 break the 18-cycle manual-takeover streak, OR did the operator have to intervene?

**Acceptance Criteria:**
- [ ] `idea-stage/dogfood-v0.9.1-findings.md` exists with the 6-section structure populated from real US-001 evidence.
- [ ] Each section cites specific log lines / quantum.json snippets (not summary-only).
- [ ] Streak status explicitly stated (broken or extended to 19).

### US-003 — Soliton-driven inline fixes

**Approach:** Per-finding triage following `references/soliton-finding-triage.md`. For each surfaced defect:
1. Validate the finding against current code (regex / static read).
2. Identify minimum scope fix.
3. Apply with TDD if testable; otherwise inline.

**Closes empty** if US-001/US-002 surface no defects (the v0.8.0 → v0.8.1 pattern allowed for this — v0.8.1 actually shipped 5 inline fixes, but v0.9.1 may ship 0 if v0.9.0 holds up).

**Acceptance Criteria:**
- [ ] Each finding from US-002 either (a) gets an inline fix with regression test OR (b) is documented as deferred with rationale (LOW severity / out-of-scope).
- [ ] If nothing surfaced: explicit "no defects surfaced; v0.9.0 holds up empirically" recorded in retrospective.
- [ ] Tests still pass: `tests/test_next_wave.sh`, `tests/test_coordinator_e2e.sh`, `tests/test_signal_parsing.sh` all green.

### US-004 — Multi-perspective post-merge review

**Approach:** STANDARD pattern across 4 v0.8.x cycles. Spawn 3 parallel review agents on the v0.9.1 cycle's diff:

- **Code-reviewer** (`oh-my-claudecode:code-reviewer`) — line-by-line on whatever fixes US-003 shipped.
- **Security-reviewer** (`oh-my-claudecode:security-reviewer`) — security implications of any new code paths.

Synthesize findings. Apply score-≥85 fixes inline (in this same cycle, not deferred).

**Acceptance Criteria:**
- [ ] 3 reviewer agents invoked in parallel (single message, multiple tool calls).
- [ ] Each agent's findings logged.
- [ ] Synthesis section writes which findings were addressed inline + which deferred (with rationale).
- [ ] No score-≥85 finding deferred.

## Test-suite delta

## Cross-cutting risk surface

1. **Real-LLM cost / wallclock** — single dogfood fire ~5-15min wallclock + ~$0.50-2.00 in tokens. Acceptable for the proof point.
2. **Worktree safety** — implementer agents commit to throwaway branch in worktree. Clean up explicitly in US-005. Never push worktree branch to remote.
3. **`--dangerously-skip-permissions`** — implementers run with this flag (per existing `claude --print` invocations). Confined to worktree filesystem; can't touch master without explicit `git push`.
4. **Reproducibility** — real LLMs are non-deterministic. v0.9.1 is a one-off proof point; not a CI test. The findings doc is what carries forward.
5. **Manual-takeover fallback** — if the dogfood deadlocks or drifts >10min, kill the parent process; manually capture state; document as "did not break streak"; ship findings + diagnostic-class fix.

## Open questions

- **Q1:** Should the dogfood synthetic bundle fire 1 wave (parallel-safe) OR 2 waves (chain US-A → US-B)? **Decision:** 1 wave (parallel-safe stories). Tests the per-wave coordinator path's actual purpose. 2-wave testing is N50/N49 territory (multi-iteration coordinator behavior).
- **Q2:** Should US-001 use `claude` or `codex`/`copilot` runner? **Decision:** `claude` (default RUNNER_NAME). Matches the production case being validated.
- **Q3:** What if the coordinator subagent fails to spawn implementers via Task tool inside the dogfood? **Decision:** Document as a v0.9.0 finding, ship inline fix in US-003, re-fire US-001.
