## Overview

1. **Test 8** does not assert the `[QL-EXECUTE] orchestrator-stale — respawning via QL_RESPAWN_CMD` diagnostic emitted by the lib (sub-threshold soliton conf-82 carry-over).
2. **Test 10** does not assert the `[QL-EXECUTE] QL_RESPAWN_CMD exited %d — respawn may have failed` diagnostic added in the soliton fix (parallel gap to Issue 1).
3. **Test 10** lacks a wall-clock guard (Test 8 has one, Test 10 doesn't — defensive consistency).

These are tracked collectively as **N28**.

## Per-story design notes

### US-001 — N28: test-adequacy fixes

**Problem:** v0.7.2 internal code review identified 3 missing assertions in Tests 8 and 10. The lib emits diagnostic log lines that are not asserted in the test suite, leaving the diagnostic path silently regressible.

**Decision:**
- **Test 8 (line ~222-235):** Add a 4th assertion that greps `out8` for `[QL-EXECUTE] orchestrator-stale — respawning via QL_RESPAWN_CMD`. This validates the lib's stderr diagnostic actually fires when QL_RESPAWN_CMD is set + STALE.
- **Test 10 (line ~255-264):** Add a wall-clock `t0`/`t1`/`elapsed` capture matching Test 8's pattern, asserting `elapsed <= 10`. Add an assertion greping `out10` for `QL_RESPAWN_CMD exited 42 — respawn may have failed`. Two new assertions.

**Files:** `tests/test_orchestrator_liveness.sh` only.

**Verification:** existing 24 assertions remain green; +3 new assertions (Test 8 +1, Test 10 +2). Total 27.
