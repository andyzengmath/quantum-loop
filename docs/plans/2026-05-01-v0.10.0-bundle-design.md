## US-001 deep-dive: PARALLEL_MODE extraction

### Block boundaries

`quantum-loop.sh` current (post-v0.9.6) contains 3 PARALLEL_MODE blocks:
- **Conditional source block: lines 318-353.** Sources `lib/dag-query.sh` + `lib/worktree.sh` + `lib/spawn.sh` + `lib/monitor.sh` + `lib/resilience.sh` (parallel-only) and `lib/dag-query.sh` + `lib/spawn.sh` (also under `--coordinator`). Stays in `quantum-loop.sh` (entry-point sourcing).
- **Mode print block: lines 383-387.** 4 lines printing "Mode: Parallel" or "Mode: Sequential". Stays in `quantum-loop.sh`.
- **Main PARALLEL_MODE block: lines 394-784.** Full agent dispatch loop. **EXTRACT THIS.**

Required globals to be received by `run_parallel_mode()` via env/sourcing scope (NOT explicit args — preserves p006 conventions):

- All helper functions sourced via the conditional block at 318-353

### Risks + mitigations

- **Trap handler scope** — `cleanup_on_exit` is defined inside the block + registered via `trap`. Trap remains in scope when defined inside a sourced function body. Verify with manual Ctrl-C test on a stub PARALLEL_MODE run.
- **`local -a` declarations** — wrapping the body in a function makes `declare -a AGENT_PIDS` etc work as locals. Currently they're top-level. Need to verify no caller in `quantum-loop.sh` accesses these post-extraction (they shouldn't — block exits at end).
- **AGENT_PIDS array global vs local** — declare as locals inside `run_parallel_mode()`. The cleanup_on_exit trap captures by-reference; since trap fires from within the function scope (still active during execution), this works.
- **Source-order** — `lib/parallel-mode.sh` MUST be sourced AFTER `lib/json-atomic.sh` (for `json_atomic_update_args`) and AFTER `lib/loop-helpers.sh` (for `emit_terminal_signal`). Both are sourced at line 277 + 367 respectively, before the new sourcing point at ~393. Safe.
- **Test coverage** — PARALLEL_MODE has no dedicated test suite. Existing `test_orchestrator_liveness.sh` covers some of the dispatch helpers but not the integration. Smoke test: stub PARALLEL_MODE invocation that exits immediately on next_wave returning empty; assert exit code + behavior preservation. Don't add a heavy new e2e suite — too costly for the cycle.

## US-002 deep-dive: 2>/dev/null symmetric hardening

```bash
json_atomic_update() {
  # ... existing prelude ...
  local stderr_tmp updated
  stderr_tmp=$(mktemp)
  trap "rm -f '$stderr_tmp'" RETURN
  updated=$(jq "$filter" "$json_path" 2>"$stderr_tmp")
  if [[ -z "$updated" ]]; then
    local err
    err=$(< "$stderr_tmp")
    printf "ERROR: json_atomic_update: jq filter produced empty output%s\n" \
      "${err:+ (jq stderr: $err)}" >&2
    return 1
  fi
  write_quantum_json "$json_path" "$updated"
}
```

Same pattern for `json_atomic_update_args`. Tests added: 2 new in `tests/test_json_atomic.sh` covering "malformed argjson surfaces jq error in our error message" — without the hardening, the error has just "filter produced empty output"; with it, the error includes jq's parse-failure detail.

## Decision points

- **Q1:** PARALLEL_MODE extraction — keep `cleanup_on_exit` + reaper trap inside `run_parallel_mode()` body? **Decision:** Yes. Trap registered via `trap ... EXIT INT TERM` from inside the function survives properly; trap handler fires when shell exits or signals. Verified pattern in iteration-loop.sh (the same wrapper-function approach).
- **Q2:** Should `run_parallel_mode()` exit with a status, or just return and let caller handle? **Decision:** `exit` (mirroring `run_iteration_loop()`). The function calls `exit 0/1/2` directly per terminal signal — no caller logic needed.
- **Q3:** Migrate 1 COMPLETE/BLOCKED pair as part of T-001-1 extraction or as separate T-001-3? **Decision:** Separate T-001-3 for clean diff readability.
- **Q4:** Real-feature dogfood (US-003) — block v0.10.0 ship on having a real feature? **Decision:** No. If no feature ready, retrospective notes US-003 deferred to v0.10.1; cycle still ships v0.10.0.
- **Q5:** Tier — minor (0.10.0) or patch (0.9.7)? **Decision:** minor (0.10.0). PARALLEL_MODE extraction is the architectural-milestone closure.
- **Q6:** Should US-004 add p013/p014 to `references/codebase-patterns.md` (new file) or CLAUDE.md? **Decision:** CLAUDE.md `## Process references` section (where they belong logically — process patterns vs coding idioms).
