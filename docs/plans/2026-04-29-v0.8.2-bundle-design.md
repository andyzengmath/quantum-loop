# Design: v0.8.2 — patch-tier (post-v0.8.1 review fixes + v0.9.0 prerequisites)

**Date:** 2026-04-29
**Status:** Approved
**Source:** Multi-perspective review of v0.8.1 ship state (architect + code-reviewer + security-reviewer agents) surfaced 2 CRITICAL items + 3 supporting follow-ups.
**Approach:** 5-story patch — fix CRLF hygiene + extend signal protocol for v0.9.0 + recurring wall-clock flake + architectural-debt docs + retrospective.
**Target version:** 0.8.2 (patch bump from 0.8.1)
**Target effort:** ~3-4 hours

## Overview

Three parallel reviewers (architect / code-reviewer / security-reviewer) examined v0.8.1's ship state at master `b1ac946`. Two **CRITICAL** items surfaced that gate v0.9.0:

1. **CRLF line endings** on `runners/hooks/copilot-hooks.sh` and `tests/test_runner.sh`. v0.8.1 US-004 imported these from a stash that was authored on Windows; they shipped CRLF-encoded. Strict Linux CI environments will fail on the shebang line (`/usr/bin/env bash\r: No such file or directory`).
2. **Signal-protocol mismatch.** `runner_parse_output` (lib/runner.sh:283) regex matches only `STORY_PASSED|STORY_FAILED|COMPLETE|BLOCKED`. The coordinator agent (`agents/coordinator.md:36-37`) emits `WAVE_PASSED`/`WAVE_FAILED`. Without extending the parser, every coordinator dispatch in v0.9.0 N42 will route to the unknown-signal branch and be marked failed. Same anti-pattern as N33 root cause #1, repeating one layer deeper *yet again*.

Plus 3 supporting follow-ups:
- **Test 5 wall-clock flake** in `tests/test_orchestrator_liveness.sh` (`interval_sec=0 guard`, 7s vs 6s ceiling) — same Git Bash subprocess-jitter class as v0.8.1 US-003's Test 2 fix.
- **`--coordinator --parallel` undefined** — these flags would produce nested parallelism (worktree-of-worktrees) that doesn't compose.
- **Quantum.json dual-writer ownership** — coordinator writes `execution.completedWaves`; parent loop writes `stories[].status`. Need an explicit ownership boundary doc before v0.9.0 ships per-wave dispatch.

**v0.8.2 framing rationale:** No new architecture. Pure post-review fix-up + v0.9.0 prerequisites. Per `feedback_version_tier_calibration.md`, default to patch.

## Per-story design notes

### US-001 — CRLF hygiene

**Problem:** `file runners/hooks/copilot-hooks.sh` and `file tests/test_runner.sh` both report "with CRLF line terminators". v0.8.1 US-004 imported these from `stash@{0}` (authored on Windows). Strict Linux environments will reject `#!/usr/bin/env bash\r` with `bad interpreter: No such file or directory`.

**Decision:** Run `dos2unix` on both files. Add `.gitattributes` rule `*.sh text eol=lf` and `*.bash text eol=lf` to prevent recurrence.

**Files:** `runners/hooks/copilot-hooks.sh`, `tests/test_runner.sh`, `.gitattributes`.

**Verification:** `file <each file>` reports "Bourne-Again shell script" without CRLF. `git diff --check` clean. Existing tests still pass.

### US-002 — Signal-parser extension for `WAVE_*`

**Problem:** Architect review caught that `runner_parse_output` (lib/runner.sh:283) recognizes only `STORY_PASSED|STORY_FAILED|COMPLETE|BLOCKED`. The coordinator agent (per `agents/coordinator.md:36-37` and `lib/spawn.sh:172-173`) emits `WAVE_PASSED`/`WAVE_FAILED`. v0.9.0 N42 will wire `spawn_coordinator` into the dispatch loop, but the parser will see `WAVE_PASSED` and fall through to the unknown-signal branch.

**Decision:** Extend the regex in `runner_parse_output` to recognize the 2 wave signals. Map them in the same SIGNAL_RESULT contract (`WAVE_PASSED` → continue to next wave; `WAVE_FAILED` → trigger retry/respawn). Add unit tests asserting parser correctness for all 6 signals.

The parser change is small (a regex extension) and must not regress existing 4-signal behavior. v0.9.0 N42 will then have a usable signal contract.

**Files:** `lib/runner.sh` (regex extension); `tests/test_signal_parsing.sh` (NEW) or extension of an existing runner test.

**Verification:** Parser unit tests pass; no regression in `tests/test_runner.sh` or any other suite.

### US-003 — Test 5 wall-clock ceiling

**Problem:** `tests/test_orchestrator_liveness.sh` Test 5 (`poll_orchestrator_commits 10 0` interval_sec=0 guard) has ceiling `<= 6` (line ~134). Re-runs after v0.8.1 ship show 7s on Git Bash. Same class as v0.8.1 US-003's Test 2 fix.

**Decision:** Bump ceiling 6 → 10s with reference annotation to `references/test-wallclock-baselines.md` (mirror the US-003 v0.8.1 pattern). Audit Tests 7, 8, 10, 11 for similarly tight ceilings; bump if observed flaky in pre-flight.

**Files:** `tests/test_orchestrator_liveness.sh`.

**Verification:** Test 5 passes consistently across 3 consecutive runs; full liveness test suite reaches 34/34.

### US-004 — `--coordinator --parallel` rejection + quantum.json dual-writer ownership

**Problem:** Architect surfaced two architectural-debt items that need documentation before v0.9.0 ships per-wave dispatch:

1. **`--coordinator --parallel` is undefined.** The parallel path already does worktree-based wave dispatch. The coordinator agent definition spawns implementer subagents internally. Combining them produces nested parallelism (worktree-of-worktrees) that doesn't compose on Git.
2. **Dual quantum.json writer.** Coordinator writes `execution.completedWaves`; parent loop writes `stories[].status` and other fields. Without an explicit ownership boundary, last-writer-wins on the non-atomic `tmp+mv` pattern.

**Decision:** Add an "Interaction with --parallel" subsection to `agents/coordinator.md` stating that `--coordinator --parallel` is rejected at CLI parse time (planned for v0.9.0; v0.8.2 documents the policy and adds a TODO marker). Add a "quantum.json field ownership" subsection to `agents/coordinator.md` defining: coordinator owns `execution.completedWaves` (and any wave-specific fields); parent loop owns `stories[].status`, `stories[].retries.*`, `updatedAt`.

**Files:** `agents/coordinator.md` (additive sections only).

**Verification:** Both new sections present (verifiable via grep). v0.9.0 design will reference them as the contract.

Standard retrospective. G30 self-validation expected LOW (small reactive patch). PIPELINE_REPORT_v24 + IDEA_REPORT_v24 (notes how v0.8.2 closes the v0.8.1 review findings + lays the v0.9.0 prerequisites). CHANGELOG [0.8.2] entry. 4-field version bump 0.8.1 → 0.8.2.

## Architecture / cross-cutting concerns

**No new architecture.** All work is post-review fix-up + v0.9.0 prerequisites + documentation.

**Backward compatibility.** US-002 (signal parser extension) is purely additive — new signal recognition without altering existing 4-signal behavior. CRLF fix has no behavioral impact on Linux (already runs LF). Test ceiling bump is test-only.

**v0.9.0 readiness.** After v0.8.2 ships, v0.9.0 N42 (real per-wave dispatch) can wire `spawn_coordinator` into the dispatch loop without the signal-protocol gap. The architectural-debt docs (US-004) become the v0.9.0 contract for `--coordinator --parallel` rejection and quantum.json field ownership.

## Risk + mitigations

| Risk | Likelihood | Mitigation |
|---|:-:|---|
| US-001 CRLF re-encoding alters file content meaningfully (hidden chars, trailing spaces) | LOW | Run `dos2unix` then `git diff --stat` — should show 0 content lines changed, only line-ending bytes. If diff shows content changes, investigate. |
| US-002 regex extension matches `WAVE_*` strings inside agent output that aren't actual signals (false positive) | LOW | The existing parser already handles this for `STORY_*` via shape filters. Extend the same shape filter to wave signals. Test with realistic agent output samples. |
| US-003 ceiling bump masks a real perf regression in `poll_orchestrator_commits` | LOW | Pre-flight measured 7s twice. If subsequent runs trend toward 12s+, escalate to a real perf investigation before merging US-003. |
| US-004 doc-only — no code risk | N/A | — |
| External-helper modifies files mid-cycle (recurring) | MEDIUM | Stash + rebase if needed. Note in retrospective. |
