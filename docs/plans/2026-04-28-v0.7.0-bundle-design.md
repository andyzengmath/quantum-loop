## Overview

v0.6.5..v0.6.9 shipped as 5 consecutive patch-tier releases (all classified score=25 LOW by `should_dispatch_deep_review`). Bundle size shrunk 7-7-7-7-5 — patch-tier backlog naturally drained. v0.7.0 marks the **first minor-tier framing** in this track, justified by:

1. **G22 calibration first pass** — the 5-cycle / 15-row patch-tier CSV baseline is now stable enough to histogram severity distributions against `references/finding-severity.md`'s expected mix. Calibration is analysis work that updates rubric language; substantive enough for minor-tier framing.

2. **N14 SKILL-level liveness wrapping** — wires `lib/orchestrator-liveness.sh::poll_orchestrator_commits` into the `/ql-execute` SKILL so unattended runs auto-detect orchestrator drift and hand off via `references/orchestrator-takeover.md`. Runtime-control-flow change (not just a doc/cleanup); minor-tier appropriate.

3. **3 LOW-priority cleanups bundled** — N15 Process references CLAUDE.md re-categorization at 4+ entries; N16 `interval_sec=0` guard in poll_orchestrator_commits (v0.6.9 soliton conf-82 carry-over); N17 REPO_ROOT shell-quoting in bench (v0.6.9 soliton conf-65 carry-over).

The bundle is **minor-tier** despite being mostly cleanup because:
- G22 changes the severity rubric language (no API but operator-facing rubric update).
- N14 introduces SKILL-level orchestrator-spawning behavior change (CI/CD-relevant).
- Patch-tier consistency would otherwise have been v0.6.10 — but the patch backlog is exhausted, so the natural framing is to absorb these into a v0.7.0 release.

**Out of scope for v0.7.0:**
- **G19** (3-SKILL-wrapper centralization) — only revisit if a 4th pre-impl-review stage is added; none materialized.
- **P5.B2/B3/B5/C** frontier — same triage as prior cycles.
- **G21** (CSV rotation) — premature at 15 rows.
- **G24** (audit relative-path) — defer.

## Per-story design notes

### US-001 — G22: severity rubric calibration first pass

**Problem:** v0.6.5..v0.6.9 produced 15 CSV rows / 41 findings / 5 cycles. The severity rubric in `references/finding-severity.md` documents an expected mix per severity tier. Without empirical comparison, rubric language could be miscalibrated (e.g., over- or under-classifying findings).

**Decision:** Author `references/severity-rubric-calibration-v0.7.0.md` (NEW). Sections:

1. **§ Methodology** — how the calibration was done. Parse `metrics/pre-impl-review-findings.csv` with awk/jq; aggregate by stage (design/prd/plan); compute histograms.
2. **§ Empirical distribution** (3 sub-tables: design / prd / plan) — count of critical/high/medium/low findings per cycle.
3. **§ Expected distribution** — quote the relevant section from `references/finding-severity.md`.
4. **§ Drift analysis** — per-severity comparison; flag categories where empirical % differs from expected % by >20 percentage points.
5. **§ Rubric language updates** — concrete edits to `references/finding-severity.md` if drift is significant. If drift is <20pp, document "no rubric updates required at this baseline; revisit at v0.7.x with minor-tier comparison data."
6. **§ Future work** — what to track in v0.7.x cycles (especially as minor-tier bundles add comparison axis).

**Files:** `references/severity-rubric-calibration-v0.7.0.md` (NEW), possibly `references/finding-severity.md` (small edits if drift found), `tests/test_severity_rubric_calibration.sh` (NEW: presence + section-headers + drift-analysis-section + cross-link from CLAUDE.md).

**Verification:** new test ≥4 assertions: file exists, 6 sections present, parse-script section exists. **Self-verifying calibration:** `tests/test_severity_rubric_calibration.sh` extracts the parse-script bash code-fence from §Methodology of the calibration doc, runs it against `metrics/pre-impl-review-findings.csv`, and asserts the output matches the §Empirical distribution table. A future cycle that re-runs the parse must produce identical numbers OR the doc must be re-snapshotted to v0.7.x. This makes the calibration doc self-verifying, not just a static snapshot.

### US-002 — N14: SKILL-level liveness wrapping

**Problem:** v0.6.9 shipped `lib/orchestrator-liveness.sh::poll_orchestrator_commits` as a library helper but `/ql-execute` SKILL did NOT yet wrap orchestrator dispatch with it. Manual operators still need to invoke the helper themselves.

**Decision:** Empirically verified `skills/ql-execute/SKILL.md` EXISTS at design-review hook time — finalizing option (a): edit the existing SKILL. Wrapper-script alternative (b) is no longer in scope for v0.7.0.

`skills/ql-execute/SKILL.md` extension adds a § "Orchestrator liveness gate" subsection that:

1. After dispatching the orchestrator subagent (which runs in the background or in a separate context), invoke `poll_orchestrator_commits` from a parent-side bash block.
2. On STALE signal (rc=1), emit a structured handoff message pointing parent at `references/orchestrator-takeover.md`. Exit the SKILL with rc=1 (`orchestrator-stale` signal).
3. Honor `QL_LIVENESS_ENABLE` env var (default `true`); when set to `false`, skip the wrapping (matches v0.6.9 backwards compat — operators who don't want the gate keep their existing behavior).

**Files:** `skills/ql-execute/SKILL.md` (extension OR new — verify at impl time). New `tests/test_ql_execute_liveness_wrapping.sh`: assert the SKILL.md contains the wrapping prose + env-var honoring + handoff-message structure.

**Verification:** ≥4 assertions: SKILL header for liveness-gate present, QL_LIVENESS_ENABLE env-var documented, orchestrator-takeover.md cross-link present, default true documented.

### US-004 — N16: interval_sec=0 guard

**Problem:** v0.6.9 PR #70 soliton finding (conf 82): if a caller passes `interval_sec=0` to `poll_orchestrator_commits`, `sleep 0` is a no-op and `elapsed` never increases — infinite loop.

**Decision:** Add guard at the top of the function:

```bash
poll_orchestrator_commits() {
  local timeout_sec="${1:-600}"
  local interval_sec="${2:-60}"
  local base_sha="${3:-$(git rev-parse HEAD 2>/dev/null)}"

  if (( interval_sec <= 0 )); then
    printf "[LIVENESS] ERROR: interval_sec must be > 0 (got %s)\n" "$interval_sec" >&2
    return 1
  fi

  local elapsed=0
  ...
```

**Files:** `lib/orchestrator-liveness.sh`, `tests/test_orchestrator_liveness.sh`.

**Verification:** new Test 5 asserts `poll_orchestrator_commits 10 0` returns 1 within <2s wall-clock + emits ERROR log line (NOT STALE).

### US-005 — N17: REPO_ROOT shell-quoting in bench

**Problem:** v0.6.9 PR #70 soliton finding (conf 65): `time eval "(cd '$REPO_ROOT' && $cmd)"` breaks if REPO_ROOT contains a single quote. Current paths safe; future clones to e.g. `/home/user/andy's-repos/` would syntax-error.

**Decision:** Use `printf %q`:

```bash
safe_cmd=$(printf '(cd %q && %s)' "$REPO_ROOT" "$cmd")
measured_raw=$( { time eval "$safe_cmd" >/dev/null 2>&1 ; } 2>&1 | grep '^real' | awk '{print $2}')
```

**Files:** `tests/bench_wallclock_baseline_drift.sh`.

**Verification:** `bash -n tests/bench_wallclock_baseline_drift.sh` passes; grep that the file contains `printf '(cd %q'` literal (proves quoting was applied).
