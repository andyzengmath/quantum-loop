## Per-story design notes

### US-001 — N24: wrap_orchestrator_dispatch auto-respawn

**Problem:** The 4-layer recovery infrastructure (v0.6.8 prose / v0.6.9 lib / v0.7.0 SKILL / v0.7.1 testable-extraction) ends at "emit handoff message + return 1". This requires manual parent-agent intervention every cycle. 5 consecutive manual-takeover cycles with 0 retries confirms the pattern is reliable but requires human attention. Auto-respawn would close the loop for unattended runs.

**Decision:** Extend `wrap_orchestrator_dispatch` in `lib/orchestrator-liveness.sh` with a `QL_RESPAWN_CMD` environment variable:

```bash
# N24 / US-001 (v0.7.2) — auto-respawn extension
# If QL_RESPAWN_CMD is non-empty and STALE is detected, execute it instead
# of emitting the manual-takeover handoff. The respawn command should be a
# fully-specified invocation of the orchestrator (e.g., `claude --skill ql-execute`).
# Return value: the exit code of QL_RESPAWN_CMD (success = 0, failure = non-zero).
# If QL_RESPAWN_CMD is empty (default): current behavior unchanged (handoff + return 1).
```

Updated `wrap_orchestrator_dispatch` logic:

```
QL_LIVENESS_ENABLE=false → return 0 (unchanged)
poll_orchestrator_commits succeeds → return 0 (unchanged)
poll_orchestrator_commits stale + QL_RESPAWN_CMD non-empty →
    printf "[QL-EXECUTE] orchestrator-stale — respawning via QL_RESPAWN_CMD\n" >&2
    bash -c "${QL_RESPAWN_CMD}"
    return $?
poll_orchestrator_commits stale + QL_RESPAWN_CMD empty →
    emit handoff message → return 1 (unchanged from v0.7.1)
```

**Test 8** (QL_RESPAWN_CMD set, STALE path): invoke `wrap_orchestrator_dispatch 2 1` against a stale tmp repo with `QL_RESPAWN_CMD="echo respawned"` → stdout contains "respawned" → rc=0. Wall-clock <10s (matches Tests 2/7 pattern).

**Test 9** (QL_RESPAWN_CMD unset, STALE path — regression): invoke `wrap_orchestrator_dispatch 2 1` with `QL_RESPAWN_CMD=""` (or unset) against stale repo → handoff message on stdout → rc=1. Confirms v0.7.1 behavior unchanged.

**Files:** `lib/orchestrator-liveness.sh` (extend wrap_orchestrator_dispatch), `tests/test_orchestrator_liveness.sh` (Tests 8 + 9).

**Verification:** 18 existing assertions green + 4 new assertions (Test 8: rc=0 + "respawned" in stdout; Test 9: rc=1 + handoff message in stdout).

## Architecture / cross-cutting concerns

**N24 security note:** `QL_RESPAWN_CMD` is an operator-controlled env var executed via `bash -c`. This is intentional — the respawn command is a trusted operator invocation, not untrusted user input. Document explicitly in the function comment to satisfy future soliton security pass.

**G22 timing dependency:** calibration snapshot must use CSV data AFTER v0.7.2 advisory hooks. The retrospective story (US-003) runs after both US-001 and US-002, and by then hooks have been fired. US-002 captures fresh parse-script output at execution time.

**Self-modifying caveat:** N24's QL_RESPAWN_CMD feature is callable; v0.7.2 dogfood does NOT exercise it end-to-end with a real claude invocation (same pattern as N20's wrap_orchestrator_dispatch — tested with an echo command, not a real orchestrator spawn).

## Risk + mitigations

| Risk | Likelihood | Mitigation |
|---|:-:|---|
| `QL_RESPAWN_CMD` eval safety concern raised by soliton | MEDIUM | Document operator-controlled intent in function comment; note in PRD. Pre-empt with explicit inline comment. |
| G22 minor-tier sample too small (n=1) for meaningful comparison | LOW | Explicitly note limitation in calibration doc; frame as "directional signal, not statistical conclusion". |
| Test 8 rc=0 conflicts with Tests 2/7 rc=1 expectations (stale path) | LOW | Tests 8/9 use different QL_RESPAWN_CMD values to exercise both branches; existing tests unaffected (they don't set QL_RESPAWN_CMD). |
