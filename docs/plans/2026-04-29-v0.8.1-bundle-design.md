**Date:** 2026-04-29

## Overview

v0.8.0 closed N33 (orchestrator drift) structurally with 7 stories: recovery wiring, worktree-aware polling, modular orchestrator (1743→1007 lines), per-wave coordinator pattern, signal unification, integration tests. The closure is **structurally complete but empirically unproven** — `wrap_orchestrator_dispatch` has never fired in a production cycle, only in stub-driven integration tests.

v0.8.1 is the validation cycle. The primary mission is to dogfood `quantum-loop.sh --coordinator` end-to-end on a small bundle, observe whether the new infrastructure actually fires (recovery, worktree-poll, bounded coordinator context), and ship inline fixes for any defects surfaced.

Pre-flight on master HEAD (e743000) surfaced two inline fixes worth folding in:

1. **Test 2 wall-clock flake** in `tests/test_orchestrator_liveness.sh` — 12s ceiling on Git Bash, observed 18s in pre-flight. The test design comment explicitly accounts for "two invocations × 2*3 jitter" but Git Bash subprocess fork overhead can push beyond the ceiling under load. `references/test-wallclock-baselines.md` already warns against unconditional absolute targets; the fix is a small ceiling bump (12s → 20s) with annotation.
2. **copilot-hooks defensive flags** — uncommitted external-helper improvement adds `--max-autopilot-continues 0 --silent --no-color --stream off --no-remote` to the copilot pre-spawn hook (cleaner stdout, deterministic dispatch, no accidental autopilot recursion). Paired test updates in `tests/test_runner.sh` validate the new flags. Currently in `stash@{0}` — needs verification + commit.

**v0.8.1 framing rationale:** No new architectural concept. Validation + 2 small inline fixes. Per `feedback_version_tier_calibration.md`, default to patch.

## Per-story design notes

### US-001 — Dogfood `--coordinator` end-to-end

**Mission:** Exercise the v0.8.0 infrastructure on a real (small) target. The dogfood target is a tiny self-task: "Add a 1-line comment to `lib/orchestrator-liveness.sh::poll_orchestrator_commits` documenting the 4th `WORKTREE_PATH` arg." This is small enough to fit a 1-story bundle, real enough to exercise the dispatch path.

**Decision:** Create a minimal `dogfood-quantum.json` (separate from the master quantum.json) with a single 1-task story. Run `bash quantum-loop.sh --coordinator --dry-run` first to confirm the path is wired (no real spawn). Then run without `--dry-run` and observe.

If `--dry-run` doesn't exist as a flag, run with `QL_LIVENESS_TIMEOUT=30` (short timeout) and a stub orchestrator script substituted via `QL_RESPAWN_CMD` to validate the wrap path without an actual LLM dispatch.

**Files:** A throwaway dogfood-quantum.json (DELETED after dogfood, not committed) and an observation log (`idea-stage/dogfood-v0.8.1-findings.md`).

**Verification:** The dogfood produces:
- A log of which lib/orchestrator-liveness.sh function calls fired (or didn't)
- Wall-clock measurements for each phase
- An honest assessment: "did the coordinator stay within bounded context?", "did recovery fire when intended?", "any unexpected diffs?"

If the dogfood reveals that `--coordinator` is broken, US-001 grows: ship a real fix instead of just observing.

### US-002 — Capture v0.8.1 dogfood findings

**Decision:** Synthesize US-001's raw observations into structured findings. Each finding categorized as:
- ✅ WORKED — infrastructure fired as designed
- ⚠️ DEGRADED — fired but with caveats (e.g., timing edge, log noise)
- ❌ BROKEN — failed entirely; needs follow-up

If any ❌ findings surface, US-001/US-003/US-004 may need to grow into substantive fixes.

**Files:** Append synthesis section to `idea-stage/dogfood-v0.8.1-findings.md`.

### US-003 — Inline fix: Test 2 wall-clock ceiling

**Problem:** `tests/test_orchestrator_liveness.sh` line 59 has `if (( elapsed <= 12 ))`. Comment claims "timeout=2 * 3 ceiling = 6, doubled for two invocations" → 12. On Git Bash with system load, fork overhead pushes elapsed to 18s. Pre-flight observed exactly this.

**Decision:** Bump 12 → 20 in line 59, update inline comment to cite `references/test-wallclock-baselines.md` Git Bash baseline. Same fix for any sibling assertions (Test 7, Test 8, Test 10) if their ceilings are similarly tight.

**Files:** `tests/test_orchestrator_liveness.sh` (single ceiling bump).

**Verification:** Re-run `bash tests/test_orchestrator_liveness.sh` — expect 34/34 pass (no flakes).

If verification passes, commit with the v0.8.1 cycle. If a flag is rejected, drop just that flag and document.

**Files:** `runners/hooks/copilot-hooks.sh`, `tests/test_runner.sh` (both already authored, just need to land).

**Verification:** `bash tests/test_runner.sh` passes; if copilot binary present, `bash tests/test_copilot_runner_smoke.sh` and `bash tests/test_copilot_dispatch.sh` still green.

## Architecture / cross-cutting concerns

**No new architecture.** All work is validation + small inline fixes.

**Backward compatibility.** No CLI surface changes. The Test 2 ceiling bump is test-only. The copilot hook flags only affect copilot dispatch (default-disabled environments unaffected).

**Honest framing.** This is the validation cycle that v0.8.0 explicitly deferred. If `--coordinator` works, v0.8.1 is the empirical proof point. If it doesn't, v0.8.1 surfaces the defect and v0.8.2 ships the real fix. Either outcome is value-add.

## Risk + mitigations

| Risk | Likelihood | Mitigation |
|---|:-:|---|
| US-001 dogfood reveals `--coordinator` is broken in non-trivial ways | MEDIUM | Document scope-grow honestly. Don't paper over — ship a real fix in US-001, defer retrospective if needed. |
| US-004 copilot flags are accepted by older copilot CLI versions but rejected by newer | LOW | Verify with `copilot --help` if binary present; drop unsupported flags individually. |
| US-003 ceiling bump masks a real regression in `poll_orchestrator_commits` performance | LOW | The 18s pre-flight measurement is plausibly platform jitter (Git Bash fork overhead). If subsequent runs show consistent 18s+, escalate to a real perf investigation. |
| Dogfood quantum.json accidentally commits as part of v0.8.1 PR | LOW | Add `dogfood-quantum.json` to `.gitignore` for the cycle; or use a clearly-marked path under `.handoffs/` which is already gitignored. |
| External-helper modifies working tree mid-cycle | MEDIUM | Already observed (5+ files modified between two `git status` calls). Stash before each phase; preserve stash entries with descriptive labels. |

## Non-goals

- **No new architecture or CLI flags.** This is empirical validation.
- **No removal of `--legacy-orchestrator` default.** That promotion (if `--coordinator` proves stable across multiple cycles) is at minimum a minor-tier decision deferred to v0.9.0+.
- **No N40 follow-up** (orchestrator.md ≤700 lines goal). Defer indefinitely per IDEA_REPORT_v22.
- **No runner integrations.** N38 (codex flag drift detection) remains LOW priority.
