## Per-story design notes

### US-001 — PS WAVE_FAILED retry accounting

**Problem:** code-reviewer found that `quantum-loop.ps1:415-418` `"WAVE_FAILED"` arm only clears `startedAt` — does NOT increment `retries.attempts` or append to `retries.failureLog`. Same class as v0.8.1 US-006 fix on bash side. PS path is secondary (not dogfood) but bug is real: infinite-retry loop.

**Decision:** Mirror the bash `WAVE_FAILED)` arm exactly:
```jq
.stories |= map(if .id == $id then .status = "failed" | .startedAt = null | .retries.attempts += 1 | .retries.failureLog += [{"phase": "wave_failed", "timestamp": (now | todate)}] else . end)
```

### US-002 — PS storyId defense-in-depth

**Problem:** security-reviewer found pre-existing PS gap (widened by v0.8.3): no `storyId` format validation before jq interpolation. `--arg` is safe (jq treats as string), but defense-in-depth is missing.

**Decision:** Add regex validation after `$storyId` assignment:
```powershell
if ($storyId -notmatch '^[A-Za-z0-9_-]+$') { Write-Error "Invalid storyId: $storyId"; exit 1 }
```

### US-003 — lib/spawn.sh source guard

**Problem:** code-reviewer found `lib/spawn.sh` lacks `_QL_SPAWN_SH` guard or equivalent. The v0.8.3 source-gate comment claims "lib/spawn.sh has its own source-guard", but that's inaccurate.

**Decision:** Add `[[ -n "${_QL_SPAWN_SH:-}" ]] && return 0; _QL_SPAWN_SH=1` at top of `lib/spawn.sh`. Idempotent re-sourcing now guaranteed.

### US-004 — Cosmetic doc gaps

**Problem:** Architect found 4 docs that list only 4 signals:
- `CLAUDE.md:296-303` — Signal Reference table
- `skills/ql-execute/SKILL.md:77-84` — signal table
- `runners/preamble.md:9-14` — signal protocol
- `templates/quantum-loop.ps1:172-193` — user template

All implementer-scoped (story-level dispatch), so not runtime risks. But documentation drift is real.

**Decision:** Add `WAVE_PASSED` and `WAVE_FAILED` rows to each table with a brief note that these are wave-level signals from the coordinator pattern.
