## Overview

The 2026-04-22 → 2026-04-26 burst delivered the entire prior IDEA_REPORT through P3 plus 5 P2 patterns. Three independent agent investigations (state-audit, competitor-delta, literature-delta) converge on a sharp picture: **the reviewer is now the bottleneck, not the coder**. 9 of the 10 items in this bundle target reviewer-tier work directly or remove friction that prevents the reviewer from operating cleanly.

The bundle is designed as **the second real dogfood** of quantum-loop's pipeline (after the v0.5.1 `--audit` feature). Where the audit-flag was a 4-story linear chain, this is **10 stories with 2-3 parallel waves** — explicitly chosen to stress the parts of the pipeline a small linear feature can't exercise (cross-story contracts, wave-boundary review, wiring tests, multi-runner dispatch).

**Out of scope for v0.6.0:**
- P5.B2-B5 (bidirectional reviewer, /ultrareview pattern, spec-review-before-impl, AgentGA tournament)
- P5.C* frontier (Attacker agent, HiveMind proxy, per-task sandbox, GEPA, Skilldex)
- P4 ecosystem integration (still upstream-blocked)

These remain queued for v0.7.0+.

**Wave 1 (parallel, 4 stories)** — independent polish:

## Per-story design notes

### P5.A1 — Watchdog orchestrator wiring

**Mechanism:** Wire `lib/watchdog.sh`'s age-tier check (5 / 10 / 30-min) and circuit-breaker into orchestrator Step 3B.3 monitor loop. Migrate watchdog's internal calls from `lib/monitor.sh:kill_agent_process` → `lib/reaper.sh:reap_agent` for platform-aware kills.

**Files:** `agents/orchestrator.md` (3-step addition under Step 3B.3), `lib/watchdog.sh` (replace 1 internal call site).

**Verification:** new `tests/test_watchdog_wiring.sh` asserts orchestrator references match expected functions. Existing `tests/test_watchdog.sh` (32 assertions) continues to pass.

**Why now:** silent failure mode flagged by agent A — circuit-breaker exists in lib but never fires at runtime. Fixes invisible reliability regression.

### P5.A2 — Cross-provider critic CLI flag + fallback

**Mechanism:** Add `--critic=auto|codex|gemini|claude|none` operator-facing flag. Default `auto` triggers existing tier-driven dispatch (`lib/deep-review.sh:304`). Explicit value overrides. `none` disables cross-provider critic entirely. **Fallback:** if specified provider's CLI binary is not on `$PATH`, log warning + degrade to `none` rather than failing the review gate.

**Files:** `quantum-loop.sh` (arg parsing), `quantum-loop.ps1` (parity), `lib/deep-review.sh` (read flag, availability check), `agents/orchestrator.md` (1-line documentation).

**Verification:** new `tests/test_cross_provider_critic_flag.sh` covers (a) auto path unchanged, (b) `--critic=none` skips critic dispatch, (c) `--critic=codex` with codex absent → graceful warning + degrade.

**Why now:** dispatch logic shipped at tier-7 in v0.5.0 but operator can't override. Required for next bundle (P5.B1) which captures the resolved choice into a snapshot.

### P5.A3 — Deslop language-autodetect regex fallback

**Mechanism:** `lib/deslop.sh:detect_language()` currently returns "unsupported" when `knip`/`ts-prune`/`vulture`/`cargo-udeps` are absent, causing silent skip. Wire fallback to `lib/dead-code.sh`'s regex-based unused-import + unused-private-helper detection (already shipped in v0.5.0). Output normalized to deslop's expected format.

**Files:** `lib/deslop.sh` (add `_regex_fallback()` helper + dispatch logic), `tests/test_deslop.sh` (add 5 fallback-path assertions).

**Verification:** new `tests/test_deslop_regex_fallback.sh` mocks tooling absence + asserts regex path runs.

**Why now:** stories on systems without the tooling currently get no slop cleanup. Cross-platform parity issue.

### P5.A4 — Runner manifests (5 missing)

**Mechanism:** Ship 5 new manifests under `runners/` with `experimental: true` flag: `opencode.json`, `devin.json`, `kiro.json`, `goose.json`, `cline.json`. Each follows `schemas/runner.schema.json` shape. Use Superpowers' OpenCode plugin pattern (`.opencode/skills/` auto-discovery) as template for the opencode manifest. **Trim CHANGELOG v0.4.1 line 76** if any of the 5 prove infeasible.

**Files:** 5 new files in `runners/`, possibly 1-line CHANGELOG edit.

**Verification:** `schemas/validate.sh` passes on all 5. `tests/test_runner_manifests.sh` extends to confirm the 12 claimed runners all have manifests. Smoke test for opencode auto-discovery.

**Why now:** public-claim drift. Users invoking unmanifested runners get cryptic failures.

### P5.A5 — PRD hash-pinning (RAGShield Level-1)

**Mechanism:** Add `prdSha` field per story in `quantum.json` schema: sha256 of the PRD file content at story creation. Orchestrator pre-flight (Step 1) compares current PRD hash against each story's `prdSha`; mismatches mark the story as `status: "stale"` requiring re-plan. Story execution sets `prdSha` from current PRD.

**Files:** `quantum.json.example` (schema), `agents/orchestrator.md` (Step 1.1 hash check), `agents/dag-validator.md` (set `prdSha` when creating stubs), `lib/json-atomic.sh` (helper `compute_prd_sha`).

**Verification:** new `tests/test_prd_hash_pinning.sh` covers (a) matched hash → execute, (b) mismatched hash → status: stale + warning, (c) missing field on legacy quantum.json → backward-compat warning, no abort.

**Why now:** spec-anchored regen is the cheapest possible drift mitigation per RAGShield 2604.00387. Single field, ~50 LOC. Foundation for P5.A6 Sprint-Contract.

### P5.A6 — Sprint-Contract handoff format

**Mechanism:** Extend `lib/handoff.sh` with a per-story Sprint-Contract JSON: `{ storyId, prdSha, acs, contracts, files, expectedTests, plannedBy, plannedAt }`. Written at `/ql-plan` exit per-story; consumed by `/ql-execute` (implementer reads at story start) AND `/ql-review` (spec-reviewer + quality-reviewer read for AC reference). Mirrors Anthropic's 2026-03-24 Generator↔Evaluator contract pattern.

**Files:** `lib/handoff.sh` (add `write_sprint_contract` + `read_sprint_contract`), `agents/orchestrator.md` (Step 2 + Step 4 references), `agents/implementer.md`, `agents/spec-reviewer.md`, `agents/quality-reviewer.md` (each reads sprint-contract at start).

**Verification:** new `tests/test_sprint_contract.sh` (8 assertions): write/read round-trip, schema validation, missing-file warning.

**Why now:** spec faithfulness across stages. The handoff doc currently captures stage-level decisions but not per-story contract. Anthropic's blog calls this out as the highest-leverage handoff structure.

### P5.A7 — Inline self-review checklists for routine gates

**Mechanism:** Replace subagent-dispatch on routine review (typecheck / lint / test / file-org) with structured inline checklists embedded in implementer + verifier prompts. Reserve subagent dispatch for **adversarial** review (cross-story conflict, intent drift, security). Per Superpowers v5.0.6: this cut review time ~25 min → ~30 sec.

**Files:** `agents/implementer.md` (add structured checklist before STORY_PASSED signal), `agents/spec-reviewer.md` (mark routine sections as inline-only), `skills/ql-verify/SKILL.md` (clarify what's inline vs adversarial).

**Verification:** `tests/test_orchestrator_wiring.sh` extended to assert inline checklist tokens present. Manual eyeball on 1 story turn-around: confirm < 60s on the routine path.

**Why now:** latency + cost. Frees subagent budget for the high-value adversarial checks (which P5.B series will introduce).

### P5.A8 — Cheapest-capable-model routing per task

**Mechanism:** Add `complexity` field per story in `quantum.json` schema, computed as a 0-100 score: `task_count × 10 + dependsOn_depth × 15 + has_security_tag ? 30 : 0 + filePaths_count × 2` (capped at 100). At dispatch (`lib/runner.sh:runner_build_cmd`), route stories with score ≤ 30 → Haiku model, 31-60 → Sonnet, 61+ → Opus (current default). Per Superpowers v5.0.0: detailed plans make most impls Haiku-able.

**Files:** `quantum.json.example` (schema), `agents/dag-validator.md` (compute score), `lib/runner.sh` (read score, select model), `agents/implementer.md` (acknowledge model selection).

**Verification:** new `tests/test_complexity_routing.sh` (12 assertions): score computation, threshold dispatch, override via story-level `model:` field.

**Why now:** cost + latency. Currently every story dispatches at tier set by orchestrator default. Detailed PRDs already constrain implementation enough that Haiku suffices for trivial-complexity stories.

### P5.B1 — Per-role provider routing with resolved-routing snapshot

**Mechanism:** Port OMC v4.12.0 mechanism. Add operator flags `--planner=<provider>`, `--critic=<provider>` (already from P5.A2), `--executor=<provider>`. **Resolved-routing snapshot**: at run start, capture the resolved choices (after auto-detection + availability checks) into `quantum.json.routing` for reproducibility (`{ planner: "claude", critic: "codex", executor: "claude", resolvedAt: "<iso>", versions: { ... } }`). Subsequent re-runs default to the snapshot unless overridden.

**Files:** `quantum-loop.sh` (3 new args), `quantum-loop.ps1` (parity), `lib/runner.sh` (per-role dispatch table), `quantum.json.example` (`routing` block schema), `agents/orchestrator.md` (Step 1 reads snapshot, Step 5/6/7 dispatches per role), `lib/deep-review.sh` (consume routing for critic dispatch — replaces P5.A2's hardcoded path).

**Verification:** new `tests/test_per_role_routing.sh` (~20 assertions): resolution, snapshot capture, replay determinism, fallback when role provider absent. Multi-runner integration test exercises (claude, codex) pair end-to-end on a 2-story toy quantum.json.

**Why now:** closes P2.9 fully. Direct port of a tested upstream mechanism (OMC v4.12.0). Addresses §4.1 OMC tight-coupling risk by making provider choice **explicit and snapshotted** rather than implicit. Visible operator-facing capability. Stresses dispatch / schema / runner registry / deep-review at once → bigger dogfood than --audit.

- Build measurements: `quantum-loop.sh --audit` after-state vs before

**Files:** `idea-stage/IDEA_REPORT_v3.md`, `idea-stage/PIPELINE_REPORT_v3.md`, `.omc/phase-N-evidence/v0.6.0-test-suite.log`.

**Verification:** Manual user review.

## Architecture / cross-cutting concerns

### Schema additions (`quantum.json`)

Three new optional fields per story (backward-compat: absent = default):
- `prdSha: string` (P5.A5)
- `complexity: number` (P5.A8)

One new optional top-level block (backward-compat: absent = current behavior):
- `routing: { planner, critic, executor, resolvedAt, versions }` (P5.B1)

`quantum.json.example` will document all three. Existing v0.5.x quantum.json files load without modification — orchestrator falls back to current behavior on missing fields with a one-line warning.

### Test-suite additions

3. `test_deslop_regex_fallback.sh` (P5.A3)
4. `test_runner_manifests.sh` (P5.A4 — extension of existing)
5. `test_prd_hash_pinning.sh` (P5.A5)
6. `test_sprint_contract.sh` (P5.A6)
7. `test_complexity_routing.sh` (P5.A8)

### Risk + mitigations

| Risk | Mitigation |
|---|---|
| Wave 1 parallel-merge conflict (4 stories touch orchestrator.md) | DAG enforces serialization within each story-set; P5.A1's orchestrator change is at Step 3B.3, P5.A5 at Step 1, P5.A6 at Step 2/4 — all distinct sections. Wave-boundary review catches accidental overlap. |
| P5.B1 tracking schema collision with existing `--runner` flag | New flags `--planner` / `--critic` / `--executor` are explicit additions, not replacements. `--runner=<single>` continues to work as today (sets all three). Tests cover both modes. |
| OMC dependency unresolved | P5.A2 ships `--critic=none` AND availability fallback. P5.B1's resolved-routing snapshot makes the OMC-vs-not-OMC choice explicit at the operator level. Combined: graceful degrade in both directions. |
| Inline checklist regression (P5.A7 lowers reviewer scrutiny on routine path) | Routine-vs-adversarial split is conservative — typecheck/lint/test/file-org only. Cross-story / intent-drift / security stays subagent-dispatched. Test assertion locks the boundary. |
| Bigger-dogfood reveals harness brittleness (10 stories vs 4) | Acceptable. The whole point of this bundle being labeled "bigger dogfood" is to surface those issues. P5.Z1 captures findings for IDEA_REPORT_v3. |

## Testing strategy

**Per-story:** each acceptance criterion maps to a verifiable test (per testFirst mandate).

**Per-wave:** wave-boundary cross-story constant scan + typecheck + full test suite + barrel/dep-manifest regen (existing `lib/wave-boundary.sh` infrastructure).

**Whole-feature (after Wave 3):** invoke `ql-deep-review` at CRITICAL tier (since this bundle touches schema + dispatch + reviewer pipeline = high blast radius). Cross-provider critic via P5.A2 / P5.B1 path itself.

**Dogfood metrics (P5.Z1):**
- Total wall-clock time
- Number of cross-story contract violations
- Number of wave-boundary failures
- Reviewer signal-to-noise (if measurable)
