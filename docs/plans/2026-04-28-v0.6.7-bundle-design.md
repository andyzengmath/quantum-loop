## Per-story design notes

### US-001 — G35: fix Test 4 hang

**Problem:** `tests/test_audit.sh` line 38 sources `quantum-loop.sh` to bring `_audit_*` helpers into scope. quantum-loop.sh begins with `set -euo pipefail` (line 2), which propagates errexit into the test shell. Test 4 (line 100) captures `do_audit`'s output via:

```bash
out=$(do_audit 2>&1)
rc=$?
```

Under inherited `set -e`, the subshell aborts when any helper called by `do_audit` exits non-zero — and the abort path interacts with bash's command-substitution wait semantics in a way that causes the test runner to hang past the 30s timeout. Masked since at least v0.6.5 master by v0.6.6's run_one double-execution bug (G31 in IDEA_REPORT_v6 / `c47e038`) which produced empty `.omc/phase-N-evidence/v*-test-suite.log` files instead of surfacing the hang.

**Decision:** Wrap the Test 4 capture in an explicit `set +e ... set -e` block (option (a) from IDEA_REPORT_v7 §G35). Less invasive than option (b) (restructure `do_audit` to never propagate non-zero exits), preserves the 41 existing audit assertions unchanged, and aligns with CLAUDE.md Platform Notes' guidance for subshell exit-code capture under strict mode.

```bash
# Test 4: do_audit stub returns 0 and prints header
echo ""
echo "Test 4: do_audit stub happy path"
set +e
out=$(do_audit 2>&1)
rc=$?
set -e
assert "do_audit exits 0" "0" "$rc"
case "$out" in
  *"=== Quantum-loop audit ==="*"Summary:"*)
    echo "  PASS: header + summary present"; PASS=$((PASS + 1));;
  *)
    echo "  FAIL: do_audit output — got [$out]"; FAIL=$((FAIL + 1));;
esac
TOTAL=$((TOTAL + 1))
```

A focused 1-block change. The `set -e` immediately re-enables errexit so subsequent tests retain the strict-mode discipline.

**Verification:**
- `bash tests/test_audit.sh` completes in <60s (was: hang at >30s with no progress past Test 4).
- Test 4 PASSes (do_audit's exit code 0 + header/summary present in output) — verifying do_audit's actual behavior, not just the new wrapper structure.
- All 45 audit assertions remain green; assertion count unchanged.
- `bash tests/run_all.sh` (new in v0.6.6) completes the full suite without timeout.

**Files:** `tests/test_audit.sh` (line 100 region — 2 added lines, 0 removed beyond the wrapper).

### US-002 — G36: guard `should_dispatch_deep_review` empty-input prod_count

**Problem:** `lib/deep-review.sh::should_dispatch_deep_review` line 176:

```bash
prod_count=$(printf '%s\n' "$files" | grep -cvE '^(tests?/|$)|(\.test\.|_test\.)' || true)
```

When `$files` is empty (e.g., a 0-file diff or a malformed patch with no `diff --git` headers), `printf '%s\n' ""` produces a single newline. `grep -cv` counts non-matching lines, and the empty-line trailing newline counts as 1 non-matching line — spuriously inflating `prod_count` to 1. This propagates into the score arithmetic and could mis-classify a 0-files diff as MEDIUM-tier (false dispatch).

The sibling function `compute_risk_score` at line 78 has the same code path BUT is preceded by `if [[ -n "$base_sha" && -n "$head_sha" ]]` which short-circuits on missing SHAs. `should_dispatch_deep_review` has no equivalent guard once it gets past the diff-path-readable check at line 145.

**Decision:** Add a `files_changed`-count guard around the `prod_count` block, mirroring the structure already present in `compute_risk_score`:

```bash
local prod_count=0
if (( files_changed > 0 )); then
  prod_count=$(printf '%s\n' "$files" | grep -cvE '^(tests?/|$)|(\.test\.|_test\.)' || true)
fi
```

`files_changed` is computed at line 155 above this section, so the guard is well-positioned. A 0-files diff now correctly produces `prod_without_test=0`, `score=0`, `tier=LOW`, decision=skip — matching the empty-diff invariant.

**Files:** `lib/deep-review.sh` (1 if-block insertion around lines 175-180).

**Verification:**
- New fixture in `tests/test_deep_review_dispatch.sh`: an empty patch file (0 `diff --git` headers) → `should_dispatch_deep_review` returns 1 (skip), score line shows `files=0 sensitive=0`, no false dispatch.
- Existing 8 fixture cases remain green (LOW-tier, MEDIUM-tier, force-override LOW, skip-override MEDIUM).
- 9 → 10 assertions in `tests/test_deep_review_dispatch.sh`.

### US-003 — G37: --parallel failure detection via xargs_rc

**Problem:** `tests/run_all.sh` line 144:

```bash
if printf '%s' "$out" | grep -qE ': 0/[0-9]+ passed'; then
  OVERALL_RC=1
fi
```

The check inspects only the formatted output stream. A test that exits non-zero but prints `Results: <P>/<T> passed` for some `P > 0` (e.g., partial-run output before a crash, or a test that fails on a final cleanup step after passing all assertions) would NOT trip the failure signal. The orchestrator inherits a green run_all status when an underlying test crashed.

**Decision:** Capture xargs's own exit code separately and OR it with the existing grep-based check. xargs returns non-zero if ANY child invocation exits non-zero (POSIX-spec'd behavior, same on Git Bash / MSYS / GNU). The capture pattern follows CLAUDE.md Platform Notes for subshell exit-code preservation under `set -uo pipefail` (the script's existing strict mode — it does NOT use `set -e`).

```bash
xargs_rc=0
out=$(printf '%s\n' "${TARGET_TESTS[@]}" | \
      xargs -P "$PARALLEL_N" -I{} bash "${BASH_SOURCE[0]}" --__one '{}' 2>&1) || xargs_rc=$?
printf '%s\n' "$out"
if (( xargs_rc != 0 )) || printf '%s' "$out" | grep -qE ': 0/[0-9]+ passed'; then
  OVERALL_RC=1
fi
```

The pre-existing `|| true` is replaced with `|| xargs_rc=$?` to preserve the exit code without aborting the script. The `(( xargs_rc != 0 ))` arithmetic test handles non-zero exits even if the formatted output happens to look clean.

**Files:** `tests/run_all.sh` (lines ~141-146 — 3-line patch).

**Verification:**
- New fixture in `tests/test_run_all.sh`: a synthetic test file that prints `=== Results: 1/1 passed, 0 failed ===` then `exit 1`. Sequential mode catches it (the `if ! run_one ...` already does). `--parallel 2` mode now ALSO catches it via xargs_rc.
- Existing 9 assertions remain green.
- 9 → 10-11 assertions in `tests/test_run_all.sh`.

### US-004 — N1: wire `should_dispatch_deep_review` into orchestrator Step 4B.5 control flow

**Problem:** `agents/orchestrator.md` Step 4B.5 (lines 1373-1418) was edited in v0.6.6 / US-004 to add a "0. Apply the dispatch gate FIRST" block. The block IS present at lines 1374-1383, BUT lacks an `else` containment — execution falls through to the live pipeline at line 1387 regardless of the gate's decision. The skip branch records the `deepReview: {decision: skip, automated: true}` entry into quantum.json AND THEN runs the same pipeline that the entry was supposed to short-circuit. The `# proceed to Step 4C` comment at line 1382 is aspirational, not load-bearing.

The empirical evidence: v0.6.6's US-007 T-003 self-validation invoked `should_dispatch_deep_review` directly via `bash -c 'source ...; should_dispatch_deep_review ...'` rather than going through the orchestrator's Step 4B.5 path. That worked but bypassed the very flow that this gate was supposed to govern.

**Decision:** Restructure the Step 4B.5 pseudocode block with explicit `if/else` containment so the live pipeline only runs in the non-skip branch:

```bash
# 0. Apply the dispatch gate FIRST. Skip the entire pipeline on LOW (or skip override).
git diff "$BASE_SHA..HEAD" > "$REPO_ROOT/.quantum-feature-diff.patch"
if ! bash -c "source '$REPO_ROOT/lib/deep-review.sh' && should_dispatch_deep_review '$REPO_ROOT/.quantum-feature-diff.patch'"; then
  echo "[DEEP-REVIEW] gate=skip — recording decision and continuing past 4B.5"
  jq --arg fid "$FEATURE_ID" --arg t "LOW-or-override" --arg r "should_dispatch_deep_review returned skip" \
    '.reviews[$fid] = {deepReview: {tier: $t, decision: "skip", rationale: $r, automated: true}}' \
    "$JSON_PATH" > "$JSON_PATH.tmp" && mv "$JSON_PATH.tmp" "$JSON_PATH"
  rm -f "$REPO_ROOT/.quantum-feature-diff.patch"
  # proceed to Step 4C
else
  rm -f "$REPO_ROOT/.quantum-feature-diff.patch"

  # 1. Compute risk score + tier from feature diff + intent-drift signal
  SCORE=$(bash "$REPO_ROOT/lib/deep-review.sh" score-from-quantum "$JSON_PATH" "$BASE_SHA" "HEAD")
  TIER=$(bash  "$REPO_ROOT/lib/deep-review.sh" tier "$SCORE")
  echo "[DEEP-REVIEW] Risk score=$SCORE tier=$TIER"

  # 2-7. (existing pipeline) — dispatch reviewers, aggregate, persist, act on verdict.
  ...
fi
```

The pre-`else` `rm -f` (line 1384 in current state) is moved into the else branch's first line so cleanup is symmetric across both branches. The dispatch pipeline body is indented under `else` to make the containment visually obvious.

**Files:** `agents/orchestrator.md` (Step 4B.5 — restructure ~30 lines around 1373-1418).

**Verification:**
- New assertion in `tests/test_deep_review_dispatch.sh` (the existing owner of `should_dispatch_deep_review` test coverage — colocates the gate-related assertions): grep that the orchestrator.md Step 4B.5 contains both `if !` and `else` keywords AND that `score-from-quantum` lives inside the else block, not after the `fi`.
- Existing orchestrator.md test coverage remains green.
- The restructuring preserves the dispatch pipeline's behavior on tier ≥ MEDIUM (verified by static read of the resulting block).

### US-005 — N2: `_audit_test_suites` doc clarification

# _audit_test_suites
