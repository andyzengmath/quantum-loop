## Per-story design notes

### US-001 — G32: G27 negative assertion

**Problem:** v0.6.5's US-002 added the positive `grep -q 'SPRINT_CONTRACT_TEST_REGEX' agents/spec-reviewer.md` assertion (Test 7h) but missed the symmetric negative assertion specified in the design doc: no uncited inline regex copies remain. Without it, a future commit could re-add the inline pattern alongside the citation and tests would still pass.

**Decision:** Add Test 7i to `tests/test_sprint_contract.sh` mirroring the negative-grep pattern of Tests 7e–7f (which cover orchestrator.md and ql-plan/SKILL.md):

```bash
# Test 7i (G32 / v0.6.6): no inline test-pattern regex copies in
# spec-reviewer.md except the citation line.
TOTAL=$((TOTAL + 1))
if [ "$(grep -E '(test_|\.test\.|spec|pytest)' agents/spec-reviewer.md \
        | grep -v 'SPRINT_CONTRACT_TEST_REGEX' \
        | grep -v -F 'see lib/handoff.sh' | wc -l | tr -d ' ')" = "0" ]; then
  echo "  PASS: agents/spec-reviewer.md has no uncited inline regex copies"
  PASS=$((PASS + 1))
else
  echo "  FAIL: spec-reviewer.md has uncited inline regex copies"
  FAIL=$((FAIL + 1))
fi
```

**Files:** `tests/test_sprint_contract.sh` (extend).

**Verification:** existing 18 sprint-contract assertions remain green; +1 new = 19/19 PASS.

### US-002 — G33: refactor Tests 34/35

**Problem:** Tests 34/35 in `tests/test_audit.sh` define `_t34_run` / `_t35_run` private helpers that copy-paste `do_audit`'s `case "$row" in *"|FAIL|"*` switch verbatim. A future regression in `do_audit`'s case patterns (e.g., changing `*"|WARN|"*` to `*"WARN"*`) would not be caught by 34/35 — only Test 33's full-flow integration. The duplication exists for a real reason (subshell exit-code capture per CLAUDE.md Platform Notes).

**Decision:** Add a `QL_AUDIT_TEST_ROWS` env-var hook in `quantum-loop.sh::do_audit` that, when set, replaces the helper-driven `ROWS` array with a synthetic newline-delimited string (or pipe-array). Tests 34/35 then call `bash quantum-loop.sh --audit` with `QL_AUDIT_TEST_ROWS` set + `QL_AUDIT_TEST_MODE=1` (the existing test-mode flag). The two-invocation `|| true` + `; echo $?` pattern continues to wrap subprocess calls per Platform Notes.

```bash
# In do_audit (after existing ROWS+= calls):
if [[ -n "${QL_AUDIT_TEST_ROWS:-}" ]]; then
  IFS=$'\n' read -ra ROWS <<< "$QL_AUDIT_TEST_ROWS"
fi
```

Tests 34/35 then become integration tests against the real function.

**Files:** `quantum-loop.sh` (`do_audit` add `QL_AUDIT_TEST_ROWS` hook), `tests/test_audit.sh` (Tests 34/35 rewrite to use real `do_audit`). 

**Verification:** existing 41/41 audit assertions remain green; the rewrite swaps internals — behavior identical.

### US-003 — G34: trim PR-metadata in comments

**Problem:** v0.6.5's commits added multi-line explanatory comments in `quantum-loop.sh` citing soliton confidence scores, G-numbers, and version tags. CLAUDE.md says "Don't reference the current task, fix, or callers ... since those belong in the PR description and rot as the codebase evolves."

**Decision:** Trim two comment blocks:

1. `_audit_format_row` (around line 134): keep the WHY ("Drill when FAIL or WARN — both signal something the operator should see"), drop the soliton-confidence + G-number + version metadata.
2. `do_audit` (around lines 405-420): keep the WHY ("Walk ROWS once and split counters by status; WARN does not trip exit"), drop the version-tag + story-ID + before-and-after summary string.

The full provenance lives in `git log`, `CHANGELOG.md`, and `idea-stage/PIPELINE_REPORT_v6.md` — operators and future maintainers can find it via `git blame` or grep.

**Files:** `quantum-loop.sh` (2 comment blocks).

**Verification:** existing 41/41 audit assertions remain green (no behavior change). Add a meta-assertion in `tests/test_audit.sh`: comment block sizes are within target (no inline `confidence` or `G-number` or `vX.Y.Z` strings in `_audit_format_row` or `do_audit` function-headers).

### US-004 — G30: codify ql-deep-review tier-decision rule

**Problem:** v0.6.5's US-007 T-007 made a manual decision to skip `ql-deep-review` because the diff was LOW-tier. The decision was correct but ad-hoc. The orchestrator should auto-invoke `ql-deep-review` at the wave-N boundary when `tier >= MEDIUM`, with explicit override syntax for force-invoke or force-skip.

**Decision:** Three coordinated changes:

1. **`lib/deep-review.sh`:** add `should_dispatch_deep_review(diff_path)` helper that returns 0/1 based on `compute_tier` against the diff. Exit 0 when tier >= MEDIUM. Honor `QL_DEEP_REVIEW=force` (always 0) and `QL_DEEP_REVIEW=skip` (always 1) env-var overrides.

2. **`agents/orchestrator.md` Step 4B.5:** add a documented gate that calls `should_dispatch_deep_review` against the bundle's diff. Default behavior: dispatch on tier>=MEDIUM. Override docs included.

3. **`tests/test_deep_review_dispatch.sh` (NEW):** fixture-driven test. 4 cases: LOW-tier diff → skip; MEDIUM-tier diff → dispatch; `QL_DEEP_REVIEW=force` + LOW-tier → dispatch; `QL_DEEP_REVIEW=skip` + MEDIUM-tier → skip.

**Files:** `lib/deep-review.sh` (extend), `agents/orchestrator.md` (Step 4B.5), `tests/test_deep_review_dispatch.sh` (NEW).

**Verification:** new test ≥8 assertions covering 4 fixture cases (each: pass-through behavior + env-var override). Existing `lib/deep-review.sh` and `orchestrator.md` test coverage remains green.

### US-005 — G31: `tests/run_all.sh` with `--quick` and `--parallel`

**Problem:** Full test-suite capture in retrospective T-002 takes long enough to bottleneck retrospective writing (~70 test files, ~2,200 assertions). Two paths: parallelize OR run only changed-file tests.

**Decision:** Ship `tests/run_all.sh` with three modes:

```bash
# Default: run everything sequentially (current behavior, unchanged)
bash tests/run_all.sh

# --quick: only changed-file test files (via git diff master..HEAD)
bash tests/run_all.sh --quick

# --parallel N: run all files in parallel via xargs -P N (default N=4)
bash tests/run_all.sh --parallel 4

# Combined
bash tests/run_all.sh --quick --parallel 4
```

Output format: aggregated `PASS`/`FAIL` counts + per-file summary line. Exit 0 iff all PASS.

For US-007 retrospective (T-002), use `bash tests/run_all.sh --parallel 4` to capture full suite faster.

**Files:** `tests/run_all.sh` (NEW).

**Verification:** new fixture test in `tests/test_run_all.sh` (or extend an existing meta-test): synthesize a 3-test-file fixture (1 PASS, 1 FAIL, 1 PASS); assert sequential mode reports 2/3 PASS + exit 1; `--quick` mode (with synthetic git state) only runs changed file; `--parallel 2` aggregates correctly.

### US-006 — p008: test-helper audit

**Problem:** Pattern p008 (sourced-script errexit propagation) was harvested in v0.6.5 but no enforcement exists. New test files could land that source production code with `set -e` and silently terminate on subshell exits.

**Decision:** Ship `tests/test_test_helpers.sh` that asserts every `tests/test_*.sh` file uses one of the safe patterns:

1. **Pattern A (function-extracted subshell + two-invocation idiom):** the file defines functions for subprocess capture and uses `out=$(fn 2>&1 || true)` + `rc=$(fn >/dev/null 2>&1; echo $?)` per CLAUDE.md Platform Notes.

2. **Pattern B (`|| true` after substitution):** every `out=$(cmd ...)` line uses `|| true` immediately.

3. **Pattern C (explicit `set +e` block scope):** the file wraps risky-substitution sections in `set +e ... set -e`.

The audit is structural: grep for `out=\$(` patterns and verify each one is followed (within a few lines) by either Pattern A's two-invocation companion, Pattern B's `|| true` on the same line, or Pattern C's `set +e` enclosure.

**Files:** `tests/test_test_helpers.sh` (NEW).

**Verification:** ≥6 assertions: existence + structure + at-least-one-pattern-found per known-safe test file. New test file passes against current `tests/test_*.sh` corpus.

## Risk + mitigations

| Risk | Likelihood | Mitigation |
|---|:-:|---|
| US-002's `QL_AUDIT_TEST_ROWS` env-var override accidentally triggers in production | LOW | Only honored when `QL_AUDIT_TEST_MODE=1` (existing test-mode gate) AND the env var is non-empty. Document as test-only. |
| US-004's tier-decision rule mis-classifies a real-world MEDIUM-tier bundle as LOW (silent skip) | MED | Default behavior dispatches when tier>=MEDIUM (inclusive). Override syntax allows force-invoke. Document failure mode in `agents/orchestrator.md` Step 4B.5 prose: "If unsure, set `QL_DEEP_REVIEW=force`." |
| US-005's `--parallel` mode hits race conditions in test fixtures (e.g., shared `metrics/` writes) | MED | `tests/run_all.sh --parallel` uses per-test `mktemp -d` sandboxes (already convention for most tests). Document any test files known to be parallel-unsafe in a `PARALLEL_UNSAFE` array; default `--parallel` behavior runs them sequentially after the parallel batch. |
| US-006's p008 audit produces false positives on legitimate code patterns not anticipated by the 3 safe-pattern checks | MED | Allow each test file to opt-out via a top-of-file marker comment `# pragma test-helper-audit: opt-out (rationale: ...)`. Audit greps for this and skips. |
