## Per-story design notes

### US-001 — N6-followup: parent-side liveness check

**Problem:** v0.6.7 + v0.6.8 both needed manual takeover when orchestrator drifted mid-cycle. v0.6.8's N6 prose guard is advisory; runtime detection requires polling commits from outside the agent's own reasoning loop.

**Decision:** New `lib/orchestrator-liveness.sh` with one library function:

```bash
# poll_orchestrator_commits(timeout_sec, interval_sec, base_sha)
# Returns 0 if a new commit lands within timeout_sec; 1 if no new commits
# observed (orchestrator stale signal). Emits [LIVENESS] log lines to stderr.
poll_orchestrator_commits() {
  local timeout_sec="${1:-600}"   # 10 min default
  local interval_sec="${2:-60}"   # 1 min poll
  local base_sha="${3:-$(git rev-parse HEAD)}"
  local elapsed=0
  while (( elapsed < timeout_sec )); do
    sleep "$interval_sec"
    elapsed=$((elapsed + interval_sec))
    local cur_sha
    cur_sha=$(git rev-parse HEAD)
    if [[ "$cur_sha" != "$base_sha" ]]; then
      printf "[LIVENESS] new commit %s observed at +%ds\n" "${cur_sha:0:8}" "$elapsed" >&2
      return 0
    fi
  done
  printf "[LIVENESS] STALE: no commits in %ds (base=%s)\n" "$timeout_sec" "${base_sha:0:8}" >&2
  return 1
}
```

The helper is invocation-only — it doesn't kill or re-spawn the orchestrator. The CALLER of the helper (parent agent or `/ql-execute` SKILL wrapper) decides what to do on stale: re-spawn orchestrator with the same bundle, hand off to parent for manual takeover, or log + continue depending on the operator's QL_LIVENESS_ON_STALE env var preference (future).

**`agents/orchestrator.md` Step 1 extension:** add a brief subsection noting that operators running `/ql-execute` in unattended mode can wrap the orchestrator with this helper. The actual wrapping is in `/ql-execute` SKILL — out of scope for this PR (separate v0.7.0 candidate if needed).

**Files:** `lib/orchestrator-liveness.sh` (NEW, ~40 lines), `agents/orchestrator.md` (Step 1 ~10-line subsection extension), `tests/test_orchestrator_liveness.sh` (NEW, ~50 lines).

**Verification:** new test asserts (structural-only — no timing-sensitive backgrounded-git race):
1. Function `poll_orchestrator_commits` is defined after sourcing `lib/orchestrator-liveness.sh`.
2. Calling `poll_orchestrator_commits 2 1` in a clean tmp repo (no new commits) returns 1 within ~3-5 s wall-clock and emits the `[LIVENESS] STALE: no commits in 2s` log line on stderr.
3. Pre-staged HEAD-advance test: pre-create 2 commits on a tmp branch (commit-A, commit-B); checkout commit-A; invoke `poll_orchestrator_commits 10 1`; in a backgrounded `(sleep 2 && git checkout commit-B)` synchronously advance HEAD. Helper observes the new SHA on its next 1s poll iteration and returns 0 with `[LIVENESS] new commit XXXXXXXX observed at +Ns` log line.
4. Default-arg behavior: invoking `poll_orchestrator_commits` with no args uses 600s/60s defaults — verifiable by inspecting the function definition (no timing-sensitive run with default timeout).
5. ≥4 assertions. Total test wall-clock target: <15 s on Git Bash (5s for stale path + ~5s for advance path + structural checks).

Replaces an earlier timing-fragile design (race-prone backgrounded `git commit --allow-empty`) per v0.6.9 design-review hook finding. Pre-staged HEAD-advance is deterministic across `sleep` jitter on Git Bash.

### US-002 — N13: orchestrator-takeover SOP doc

**Problem:** Manual takeover happened in v0.6.7 + v0.6.8 (2 consecutive cycles). The pattern works but is unwritten — a future operator hitting the same drift pattern has to rediscover the recovery steps.

**Decision:** New `references/orchestrator-takeover.md` (~80 lines, 4 sections):

1. **When to detect drift** — symptoms: agent abandons mid-cycle, commits stop landing, agent reasoning references "later stories" or "background work" while current story isn't `passed`. Cite v0.6.7 + v0.6.8 examples.

2. **What to verify before taking over** — `git log c1eafc2..HEAD --oneline` (look for last expected `feat: US-XXX` commit), `jq '.stories[] | select(.status=="in_progress")' quantum.json` (identify the current story), `git diff` (check what's uncommitted that the orchestrator started but never committed).

3. **How to take over without corrupting state** — preserve the orchestrator's existing in-progress edits unless a verification check (test failure, lint failure, audit assertion) proves an edit broke something. The v0.6.7 manual takeover amended the Test 4 wrapper from Pattern C (`set +e` block) to Pattern A (two-invocation idiom with `|| true`) because Pattern C tripped `tests/test_test_helpers.sh`'s corpus baseline cleanliness check — that's a **verification-failure-driven amendment**, which IS allowed. Other in-progress edits (e.g., partial test additions, comment changes the orchestrator started) should be preserved as-is and continued. Pattern: **amend only when an existing assertion or quality gate proves the orchestrator's edit broke something.** Continue from the working state otherwise. Commit normally with `feat: US-XXX - <Title>` messages. Update quantum.json `progress[]` array AT THE END (not mid-flight) so the orchestrator's own state writes don't conflict with the parent's.

4. **Cross-link from N6-followup** — when the liveness-check helper emits STALE, the parent reads this doc to continue.

**Files:** `references/orchestrator-takeover.md` (NEW), `CLAUDE.md` (cross-link in Process references section — bundled with N7's section), `tests/test_orchestrator_takeover_doc.sh` (NEW).

**Verification:** existence + 4 sections + cross-link + worked example (v0.6.7 or v0.6.8 takeover narrative).

### US-003 — N9-followup: baseline-drift WARN-test

**Problem:** v0.6.8 N9 baselines doc is hand-updated. A future drift in test-suite size or per-process startup overhead silently invalidates the table.

**Decision:** New `tests/bench_wallclock_baseline_drift.sh` runs each documented baseline command with `time`, parses the wall-clock from stderr, compares against the baseline table parsed from `references/test-wallclock-baselines.md`. Emits WARNING (not FAIL) if measured > 50% over baseline.

```bash
# Baseline table parsed from references/test-wallclock-baselines.md.
# Format: "command<TAB>git_bash_baseline_seconds"
declare -A BASELINES=(
  ["bash tests/test_audit.sh"]=240
  ["bash tests/run_all.sh --parallel 4"]=480
  ["bash tests/test_run_all.sh"]=30
  ["bash tests/test_deep_review_dispatch.sh"]=20
  # ...
)

for cmd in "${!BASELINES[@]}"; do
  baseline=${BASELINES[$cmd]}
  measured=$( { time eval "$cmd" >/dev/null 2>&1 ; } 2>&1 | awk '/^real/{print $2}' | sed 's/[ms]/ /g' | awk '{print $1*60+$2}' )
  threshold=$(( baseline * 150 / 100 ))
  if (( measured > threshold )); then
    echo "WARN: $cmd took ${measured}s (baseline ${baseline}s, threshold ${threshold}s — drift > 50%)"
  fi
done

# Always exits 0 — this test is informational only. Never FAILs.
exit 0
```

**Files:** `tests/bench_wallclock_baseline_drift.sh` (NEW, ~80 lines).

**Verification:** new test asserts:
1. The test script exists and is executable.
2. Running the test in normal conditions emits 0 WARN lines (current state matches baselines).
3. The test exits 0 unconditionally (never FAILs).
4. Synthetic drift (mock baseline = 1s, measured 30s) emits a WARN line containing "drift > 50%".

**Concern resolved (v0.6.9 design-review hook):** `tests/run_all.sh`'s glob is `tests/test_*.sh`. By naming the file `bench_wallclock_baseline_drift.sh` (no `test_` prefix), the runner deliberately skips it — operators must invoke directly: `bash tests/bench_wallclock_baseline_drift.sh`. No CI wall-clock impact. Documented in the script's header.
