## Overview

v0.9.1 shipped a known-issue advisory: implementer subagents may run destructive `git` operations in shared coordinator worktrees. The coordinator's self-healing observed in v0.9.1's dogfood was **emergent, not engineered**. v0.9.2 ships the engineered safety net.

Mirrors v0.8.x's pattern (validation cycles followed by defensive-hardening patches that close finding advisories before they bite real-feature dispatch).

**v0.9.2 framing rationale (patch-tier):** No new architecture. Adds a small helper library (`lib/coordinator-guard.sh`), a `quantum-loop.sh` case-branch gate, and a `lib/dag-query.sh` validation hook. Defensive hardening, not new capability. Per `feedback_version_tier_calibration.md`, default patch-tier unless genuinely architectural. Operator-confirmable to minor-tier if the new helper library is judged architecturally novel.

## Per-story design

### US-001 — Coordinator HEAD-snapshot guard (closes 5a HIGH)

**Problem:** v0.9.1 dogfood surfaced an implementer running `git reset --hard d66aaf8` mid-wave. Coordinator self-healed via emergent recovery. Real-feature dispatch may not recover.

**Decision:** new helper library `lib/coordinator-guard.sh` with `guard_head_advance HEAD_BEFORE [HEAD_AFTER]`:

```bash
# guard_head_advance(head_before, [head_after=HEAD])
# Returns 0 if HEAD_BEFORE is an ancestor of HEAD_AFTER (i.e., new commits
# only added on top — no destructive reset). Returns 1 + stderr message
# otherwise. Per v0.9.1 US-004 security review: ordinal SHA comparison is
# insufficient (implementer can `reset --hard && commit` to advance HEAD
# past snapshot). Ancestry check via `git merge-base --is-ancestor` is
# mandatory.
guard_head_advance() {
  local head_before="${1:?guard_head_advance: HEAD_BEFORE required}"
  local head_after="${2:-HEAD}"
  if ! git merge-base --is-ancestor "$head_before" "$head_after" 2>/dev/null; then
    printf "ERROR: guard_head_advance: HEAD reset detected — %s not ancestor of %s\n" "$head_before" "$head_after" >&2
    return 1
  fi
  return 0
}
```

**Coordinator instruction amendment** (`agents/coordinator.md` step 2):

```diff
- 2. **Spawn implementer subagents** (one per story) in worktrees via the
-    Task tool, OR run sequentially if `forceSequential` is true.
+ 2. **Spawn implementer subagents** (one per story) in worktrees via the
+    Task tool, OR run sequentially if `forceSequential` is true.
+    **Before each implementer dispatch:** capture `HEAD_BEFORE=$(git rev-parse HEAD)`.
+    **After each implementer's commit:** call `bash lib/coordinator-guard.sh guard_head_advance "$HEAD_BEFORE"`.
+    If the guard returns non-zero, the implementer ran a destructive
+    git operation. Mark the story `failed` in review fields, do NOT
+    proceed to next implementer until HEAD is rolled back to a known
+    state (operator decision; coordinator should signal WAVE_FAILED).
```

**Acceptance Criteria:**
- [ ] `lib/coordinator-guard.sh` exists with `guard_head_advance` function and CLI entry-point.
- [ ] Function uses `git merge-base --is-ancestor` (NOT ordinal comparison).
- [ ] Function returns 0 on legitimate advance, 1 on reset/non-ancestor with stderr message.
- [ ] `agents/coordinator.md` step 2 amended with HEAD_BEFORE capture + post-dispatch guard call.
- [ ] New `tests/test_coordinator_guard.sh` with ≥4 cases: (a) ancestor advance returns 0; (b) reset to prior commit returns 1; (c) reset-and-recommit (advances past snapshot but not ancestor) returns 1; (d) missing HEAD_BEFORE arg fails fast.
- [ ] All 4 cases pass.

### US-002 — Gate legacy STORY_* case branches under coordinator mode (closes code-reviewer MEDIUM)

**Problem:** `quantum-loop.sh:1673-1688` `STORY_PASSED`/`STORY_FAILED`/`BLOCKED` case branches use scalar `$STORY_ID`. Under coordinator mode, the contract requires `WAVE_*` signals only — these branches should never fire. But a coordinator bug could emit `STORY_PASSED` and orphan wave members `in_progress`.

**Decision:** add an early-check at the top of each STORY_* branch:

```bash
STORY_PASSED)
  if [[ "$COORDINATOR_MODE" == "true" ]]; then
    printf "WARNING: Unexpected STORY_PASSED under coordinator mode (expected WAVE_*). Wave members may be orphaned. Treating as WAVE_FAILED for safety.\n" >&2
    # Fall through to WAVE_FAILED branch (per-story aggregation from review fields).
    SIGNAL_RESULT="WAVE_FAILED"
    continue
  fi
  printf "Story %s PASSED. Continuing to next story...\n" "$STORY_ID"
  json_atomic_update "..."
  ;;
```

(Same gate for `STORY_FAILED` + `BLOCKED`.)

**Acceptance Criteria:**
- [ ] All 3 STORY_* case branches have a coord-mode check that logs a WARNING and falls through to `WAVE_FAILED` (which already has per-story aggregation logic from v0.9.0 US-003).
- [ ] Existing legacy-mode behavior unchanged (verifiable via diff in non-coord branches).
- [ ] `tests/test_signal_parsing.sh` continues to pass (parser unchanged).
- [ ] `bash -n quantum-loop.sh` clean.
- [ ] New regression-guard test in `tests/test_coordinator_e2e.sh` (or new file): under coord mode, simulate a STORY_PASSED signal and assert the WARNING printed + fall-through to WAVE_FAILED handling.

### US-003 — `filePaths` validation gap (closes architect MEDIUM)

**Problem:** `lib/dag-query.sh:142-172` `filter_file_conflicts` reduce-loop bypasses stories with empty `tasks[].filePaths` arrays (length=0 evaluates as "no overlap"). Operator PRDs under time pressure may omit `filePaths`. Result: silent conflict-filter bypass.

**Decision:** new `lib/quantum-validate.sh::validate_story_filepaths`:

```bash
# validate_story_filepaths(quantum_json_path)
# Warns on stdout (returns 0) for any story whose tasks[].filePaths is empty
# AND whose status is pending|failed|in_progress (i.e., would be eligible).
# Hooked into next_wave's preamble for advisory printing — does NOT block.
validate_story_filepaths() {
  local json_path="${1:?validate_story_filepaths: path required}"
  jq -r '.stories[] |
    select(.status as $s | ["pending","failed","in_progress"] | index($s)) |
    select((.tasks // [] | map(.filePaths // []) | add // []) | length == 0) |
    "WARNING: Story \(.id) has no filePaths in tasks; filter_file_conflicts will bypass it (silent risk)."
  ' "$json_path" >&2
}
```

Wire into `next_wave`'s preamble (advisory only — doesn't fail; just warns to stderr).

**Acceptance Criteria:**
- [ ] `lib/quantum-validate.sh` exists with `validate_story_filepaths` function.
- [ ] `lib/dag-query.sh::next_wave` calls it once per invocation (advisory; warnings to stderr; never blocks).
- [ ] New `tests/test_quantum_validate.sh` with ≥3 cases: (a) story with filePaths emits no warning; (b) story with empty filePaths emits warning; (c) `next_wave` still returns correct rc/output even when warnings fire.
- [ ] All 3 cases pass.

## Cross-cutting risk surface

1. **HEAD-snapshot guard runtime cost** — `git merge-base --is-ancestor` is fast (single git plumbing call). Per-implementer-dispatch overhead ~10ms.
2. **Coordinator instruction adherence** — the guard helper exists in shell, but the coordinator (LLM subagent) must remember to call it. Risk: real LLM may forget under context pressure. Mitigation: explicit instruction in `agents/coordinator.md` step 2; future hardening could be a wrapper helper that the coordinator MUST invoke.
3. **`filePaths` validation false positives** — stories that legitimately have no `filePaths` (e.g., docs-only stories with command-runner tests) will trigger warnings. Mitigation: warning is advisory; doesn't block.
4. **Wave dispatch under v0.9.2 self-test** — wave-1 is {US-001, US-002, US-003} (3 stories file-disjoint). If we use --coordinator for THIS cycle's execution, it serves as a v0.9.0 wires re-validation. Operator decision; default to legacy under manual takeover unless explicitly opted in.
5. **Real-LLM dogfood cost** — same as v0.9.1: ~5-15min wallclock + ~$0.50-2.00 in tokens. Acceptable.
