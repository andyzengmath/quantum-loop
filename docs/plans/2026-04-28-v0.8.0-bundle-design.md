# Design: v0.8.0 — minor-tier (N33 orchestrator drift root-cause closure)

**Date:** 2026-04-28
**Status:** Approved
**Source:** Operator-scoped N33 closure; informed by 5-agent root-cause research synthesis
**Approach:** 7-story bundle — wire recovery + worktree-aware liveness + modularize orchestrator + per-wave coordinator + signal unification + integration tests + retrospective
**Target version:** 0.8.0 (minor bump from 0.7.10) — first minor since v0.7.0
**Target effort:** ~5-8 hours

## Overview

For 12 consecutive cycles (v0.6.7..v0.7.10), the orchestrator subagent has abandoned its cycle mid-execution and required parent-agent manual takeover. Five recovery layers were shipped (prose / lib / SKILL / callable / auto-respawn) — none have ever auto-fired.

**Root-cause synthesis** (from 5 parallel research agents):

1. **Recovery infrastructure is inert.** `wrap_orchestrator_dispatch` and `poll_orchestrator_commits` have **zero production callers**. `quantum-loop.sh` does not source `lib/orchestrator-liveness.sh`. The "caller" of `wrap_orchestrator_dispatch` is markdown prose in `skills/ql-execute/SKILL.md` read by the same drifting LLM.
2. **Context saturation.** `agents/orchestrator.md` is 1,743 lines / ~39,900 tokens (~30% of a 200k window before any work). Static load on a 7-story bundle = ~65–70k; growing to 95–130k by Step 6.
3. **No per-story re-prompt** for orchestrator — runs entire feature lifecycle in one subagent context. "Return to Step 2" is implicit prose.
4. **Signal protocol asymmetry.** Orchestrator LLM uses ad-hoc `TaskOutput` grep; never calls `runner_parse_output`. Two parallel detection paths can disagree.
5. **`git rev-parse HEAD` mismatch in worktree mode** — `poll_orchestrator_commits` polls parent HEAD; orchestrator commits land in `.ql-wt/<story>/` on feature branches.

**v0.8.0 framing rationale:** This is the first new architectural concept since the multi-runner foundation (v0.7.4 N5). It introduces (a) production wiring for inert infrastructure, (b) a per-wave coordinator pattern, (c) modular orchestrator definition, (d) unified signal handling. **Genuinely minor-tier.**

## Per-story design notes

### US-001 — Wire recovery infrastructure

**Problem:** `wrap_orchestrator_dispatch` exists in `lib/orchestrator-liveness.sh` but no shell sources the lib, no caller invokes the function. Recovery is dead code.

**Decision:** In `quantum-loop.sh`, source `lib/orchestrator-liveness.sh` near the existing `lib/spawn.sh` source line. Around the orchestrator-spawn call, invoke `wrap_orchestrator_dispatch` so STALE detection actually fires. The wrapper is opt-in via `QL_LIVENESS_ENABLE` (default true) — preserves backward compat.

**Files:** `quantum-loop.sh` (source + wrap call), `lib/orchestrator-liveness.sh` (no signature change).

**Verification:** New test `tests/test_quantum_loop_recovery.sh` invokes `quantum-loop.sh` with `QL_LIVENESS_ENABLE=true` against a stub orchestrator that doesn't commit; expects handoff message in stderr and non-zero rc within ~10s.

### US-002 — Worktree-aware polling

**Problem:** `poll_orchestrator_commits` polls `git rev-parse HEAD` in `pwd`. Orchestrator commits in worktree mode land under `.ql-wt/<story>/`; parent HEAD doesn't advance. Wrapping in worktree mode would produce false-positive STALE.

**Decision:** Extend `poll_orchestrator_commits` signature to accept `WORKTREE_PATH` 4th positional arg. When set, polling uses `git -C "$WORKTREE_PATH" rev-parse HEAD` instead. Default (unset) preserves current behavior.

```bash
poll_orchestrator_commits TIMEOUT_SEC INTERVAL_SEC BASE_SHA WORKTREE_PATH
  # When WORKTREE_PATH is set (and not "."), poll that path's HEAD
```

`wrap_orchestrator_dispatch` gains an optional 3rd arg `WORKTREE_PATH` that propagates to the poll.

**Files:** `lib/orchestrator-liveness.sh`, `tests/test_orchestrator_liveness.sh` (new tests).

### US-003 — Modularize `agents/orchestrator.md`

**Problem:** 1,743 lines / ~39,900 tokens / ~30% of context window before any work begins. Optional sections (3A.5B/C/D/E for slop/dead-code/intent-graph/skeleton-drift, 3C.NEG0/1, type-audit, hyclone, etc.) consume context unconditionally even when their underlying lib modules aren't available.

**Decision:** Extract optional sections to `agents/orchestrator-modules/*.md`:
- `slop-cleanup.md` (3A.5B)
- `dead-code-detection.md` (3A.5C)
- `intent-graph.md` (3A.5D)
- `skeleton-drift.md` (3A.5E)
- `type-audit.md` (3C.0)
- `hyclone.md` (3C.NEG0)
- `constant-scan.md` (3C.NEG1)
- `tracecoder.md` (related sourcing)

Replace each section in `orchestrator.md` with a 2-line stub: "If `lib/<module>.sh` is sourced and `<helper>` is defined, see `agents/orchestrator-modules/<module>.md` for the full procedure. Otherwise skip."

**Target:** orchestrator.md ≤15,000 tokens (~62% reduction). Extracted module docs are referenced lazily — only the orchestrator LLM reads them when invoking that module's behavior.

**Files:** `agents/orchestrator.md` (slim), 8 new `agents/orchestrator-modules/*.md`.

### US-004 — Per-wave coordinator pattern

**Problem:** Orchestrator runs entire feature lifecycle in one context. No per-story or per-wave reset. Implementer pattern (which works) has fresh prompt per story.

**Decision:** Introduce `agents/coordinator.md` — a thin agent that handles exactly ONE wave at a time. Top-level `quantum-loop.sh` orchestrates the wave loop in shell; per-wave it spawns the coordinator with a focused prompt:

```
Coordinator scope:
- One wave (set of parallel-safe stories from quantum.json's DAG)
- Spawn implementer subagents (or run sequential) for each story in the wave
- Aggregate results
- Signal WAVE_PASSED / WAVE_FAILED to parent
- Exit
```

`quantum-loop.sh` reads quantum.json after each wave, picks the next eligible wave, spawns a fresh coordinator. This breaks the long-running orchestrator into N smaller per-wave invocations, each with bounded context.

**Files:** `agents/coordinator.md` (NEW), `lib/spawn.sh` (coordinator spawn helper), `quantum-loop.sh` (wave loop).

**Backward compat:** `agents/orchestrator.md` retained for legacy single-context flow. `quantum-loop.sh --legacy-orchestrator` flag preserves the old path. New default uses coordinator pattern.

### US-005 — Signal protocol unification

**Problem:** Orchestrator does ad-hoc `<quantum>...</quantum>` grep on `TaskOutput`. Shell-side `runner_parse_output` does the same plus heuristic fallback + claim-check. Two parallel detection paths; can disagree; no shared state.

**Decision:** `agents/orchestrator.md` (and `coordinator.md`) document the canonical signal extraction via `runner_parse_output` invocation. The orchestrator/coordinator agent definitions instruct the LLM to use the shared shell function rather than grep `TaskOutput` directly. Add a brief `runner_parse_subagent_output(agent_id)` wrapper that retrieves `TaskOutput` and feeds through `runner_parse_output`.

**Files:** `lib/runner.sh` (new wrapper function), `agents/orchestrator.md` (signal section), `agents/coordinator.md` (signal section).

### US-006 — Integration tests

**Problem:** None of the recovery infrastructure has been validated end-to-end. Tests prove function definitions exist; nothing proves the layers fire when invoked from `quantum-loop.sh`.

**Decision:** Three integration tests:
- `tests/test_quantum_loop_recovery.sh` — invoke `quantum-loop.sh` with stubbed orchestrator (no commits); expect liveness STALE detection within wall-clock ceiling.
- `tests/test_orchestrator_liveness.sh` — extend with worktree-path tests for US-002.
- `tests/test_coordinator_dispatch.sh` (NEW) — verify coordinator agent definition exists, has expected sections, and `lib/spawn.sh::spawn_coordinator` (or equivalent) builds a valid command.

**Note:** This is NOT a full dogfood (running an actual coordinator-driven cycle); that's deferred to v0.8.1 validation. v0.8.0 ships the infrastructure with unit + integration coverage.

## Architecture / cross-cutting concerns

**Backward compatibility.** All existing behavior preserved via opt-in/legacy flags. `agents/orchestrator.md` continues to exist (used by `--legacy-orchestrator`). New coordinator pattern is the default but operators can revert.

**Test pyramid.** Unit tests for individual functions; integration tests for cross-component flows. Full dogfood (running a real cycle through the new pattern) deferred to v0.8.1 — that's the validation cycle that actually exercises the recovery in anger.

**Documentation refresh.** `CLAUDE.md` Process references will need new pointers to `agents/coordinator.md` and the coordinator pattern. `references/orchestrator-takeover.md` annotated to note new auto-recovery path.

**Risk: scope sprawl.** 7-story bundle is the largest in 14 cycles. Honest limitation — if any story takes substantially longer than estimated, defer the remainder to v0.8.1.

## Risk + mitigations

| Risk | Likelihood | Mitigation |
|---|:-:|---|
| US-003 modularization breaks orchestrator behavior (extracted prose was load-bearing) | MEDIUM | Run full test suite after extraction; preserve all referenced lib functions; keep stub references in orchestrator.md so the LLM knows when to follow each module reference. |
| US-004 coordinator pattern requires changes in `quantum-loop.sh` that risk regressing existing CLI | MEDIUM | Implement behind `--coordinator` flag initially; only flip default after US-006 integration tests pass. |
| US-006 integration tests are flaky (timing-dependent) | LOW | Use deterministic stubs (a script that explicitly does no commits and exits cleanly) rather than real subagent invocations. |
| Bundle exceeds 8h target → context fatigue → regression | MEDIUM | If at story 5 wall-clock > 4h, descope US-004 to a thin spec doc + defer implementation to v0.8.1. |
