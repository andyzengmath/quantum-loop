## Patterns observed

### What worked well

1. **TDD discipline held throughout.** Every story with `testFirst: true` (US-001 T-001, US-002 T-001, US-003 T-001, US-004 T-001, US-005 T-001, US-006 T-001) explicitly verified RED state before writing the GREEN implementation. The Run 1 → Run 2 hand-off worked cleanly precisely because Run 1 had already added the RED test assertions; Run 2 inherited a clear signal (the failing tests) and a clear next step (write the GREEN).

2. **Subshell-exit-code idiom catch.** US-001's Tests 34-35 originally written as inline `out=$(... exit "$any_fail")` subshells caused the test script to terminate silently after Test 34's PASS line. Diagnosed via minimal-repro bash script. Mitigation: extract subshell body into a named function (`_t34_run`), use the two-invocation idiom (`out=$(fn 2>&1 || true); rc=$(fn >/dev/null 2>&1; echo $?)`). Added as new codebasePattern p008 — the third pattern reinforcing this gotcha.

3. **Surgical-change discipline kept stories focused.** US-005 surfaced a follow-up gap (`_audit_format_row` only renders FAIL drills, so the new WARN guidance is captured by tests but invisible at runtime). Resisted the temptation to fix it inside US-005's diff; logged the gap in US-005's progress entry + IDEA_REPORT_v6 G29 instead. Each story's diff stays tight.

4. **AC literal text vs natural prose form.** US-004's acceptance criteria specified lowercase phrases ("shared mutable state", "race window without"); the natural Markdown form Title-Cases bold checklist labels. Solution: introduce `assert_grep_ci` (case-insensitive) helper in the new test file with explicit comment explaining the AC-vs-rendered-form rationale. Cleaner than forcing an unnatural doc form.

### Recurring patterns reinforced

- **p005 strip `\r` defensively** — not directly hit this run (no jq-fed loops), but the pattern is structural.
- **p006 single source of truth for shell constants** — directly exercised by US-002 closing G14's 5th call site. The grep-needle assertion (sub-test 7h) caught the missed enumeration; pattern is healthier than v0.7.0 retrospective suggested.
- **p007 atomic critical section MUST cover all observably-coupled operations** — operationalized into a reusable design-craft checklist by US-004 (`references/risk-mitigation-language.md`). Pattern + reference doc paired across releases is a healthy signal.

### Suggested improvements for the pipeline

1. **Retrospective baseline-comparison should NOT use `git stash` + `git checkout master`** (US-007 code-quality issue). Late in the retrospective, an attempt to compute a master-baseline assertion count via `git stash --keep-index --quiet && git checkout master -- tests/ && ... && git stash pop` clobbered the working tree. Recovered cleanly via `git restore --staged --worktree` + `git stash pop`, but the diagnosis cost ~10 minutes. **Recommendation**: use a separate worktree (`git worktree add /tmp/ql-baseline master`) for any baseline-comparison work; never stash + checkout-from-master inside the active worktree.

2. **Test-suite runtime is becoming a retrospective bottleneck** (G31 in IDEA_REPORT_v6). Capturing the full test-suite log during T-002 took several minutes of background execution; report-writing finished before the suite did. With ~73 test files and 2200+ assertions, the sequential `for t in tests/*.sh` will keep growing. Two paths: parallelize via `xargs -P` (test files appear independent — verify) OR add a `--quick` retrospective mode that runs only the test files the diff touches. Either gates future retrospective velocity.

3. **ql-deep-review tier-decision rule should be machine-readable** (G30 in IDEA_REPORT_v6). v0.6.4's "deep-review skipped at Wave 2" gap was closed for v0.6.5 by documenting the tier-driven decision in PIPELINE_REPORT_v6 + recording the SKIP verdict in `quantum.json.reviews[]`. But the rule itself is not codified anywhere outside this retrospective. v0.6.6 should update `agents/orchestrator.md` Step 4B.5 to gate dispatch on `tier >= MEDIUM` and add a fixture-driven test, so future releases auto-enforce.

- **p008 — Sourced-script errexit propagation in test files.** When a test file `source`s production code that runs `set -euo pipefail`, errexit becomes active in the test scope.
