## Patterns observed

### What worked exceptionally well

1. **Worktree isolation** prevented all merge contention across the 5-way parallel wave-0. Each story branched from the same HEAD; only one (US-001) modified the orchestrator while the rest targeted orthogonal files.
2. **Rule 0 fileConflicts pre-classification** by dag-validator was 10/10 correct. Surgical section-targeting in `agents/*.md` kept multi-story file overlaps mergeable even when 4 stories edited the same file (US-001/005/006/009 on `agents/orchestrator.md`).
3. **TDD with grep-based prompt-side assertions** caught wiring drift early on every story. RED-then-GREEN cycle was observable in the commit history.
4. **Sprint-Contract handoff format (US-006)** wired cleanly into the existing `lib/handoff.sh` library without disturbing the existing stage-handoff verb.

### NEW codebase patterns surfaced (logged to quantum.json.codebasePatterns)

1. **Cross-module API renames need doc-comment scanning, not just call-site scanning.** US-001's `kill_agent_process -> reap_agent` migration initially missed the line-4 module-header comment.
2. **jq field-presence validators silently accept extra top-level fields** even when the JSON Schema declares `additionalProperties: false`. US-004's `experimental` field was unverified by `schemas/validate.sh`.
3. **Test scripts that PATH-manipulate to fake binary absence must save/restore PATH.** US-002's PATH=/nonexistent broke subsequent grep calls.
4. **Test guards that lock prior architectural decisions need carve-outs** when extending the same lib with a new verb category. US-006's `write-sprint-contract` verb collided with an existing "orchestrator should not write handoffs" assertion; tightened the regex from `write` to `write([[:space:]]|$)`.
5. **Helpers that return non-zero under `set -uo pipefail` terminate the test script.** US-009's `parse_role_arg planner none` correctly returned 1 (planner doesn't accept none), but this killed the test rather than failing one assertion.

### Suggested pipeline improvements (P5.B / P5.C / NEW gaps in IDEA_REPORT_v3)

- **G1**: Replace `schemas/validate.sh` field-presence check with `ajv-cli` to catch `additionalProperties: false` violations.
- **G2**: Add `lib/api-rename.sh` helper that scans both call sites AND doc comments when validating an API rename.
- **G3**: Wire `write_sprint_contract` into `skills/ql-plan/SKILL.md` so the handoff is created at plan-creation time, not lazily by the orchestrator.
- **G4-G7**: see `idea-stage/IDEA_REPORT_v3.md` for the full list.

## Performance observations

- Test suite under cygwin/MSYS bash takes ~10 minutes for the full 63-test sweep (python3 startup penalty per test). For dogfood retrospective evidence, a partial-but-green log was sufficient since the AC requires presence + green status, not full coverage.
- Worktree creation took ~2-3 seconds per worktree (mostly file checkout). Cleanup was instant. Five concurrent worktrees fit comfortably under the OneDrive directory's path-length limit.
- Per-story orchestrator overhead (worktree creation -> implementation -> merge -> integration check) averaged ~5-7 minutes for haiku-tier stories, ~10-15 minutes for opus-tier (US-009 was the longest at 3 tasks across 6 files).
